## 현재 범위

<!-- CURRENT-SCOPE-BEGIN -->
**현재 단계의 개발·학습·평가 대상은 X500 기준 기체 한 구성으로 한정한다.** 하나의 정상 비행만 사용한다는 뜻은 아니다. 같은 X500 기준 구성에서 건강한 모터·배터리·프로펠러·ESC·센서로 다양한 허용 기동·바람·탑재량·잔량·온도 조건의 정상 비행을 생성한다.

**이번 산출물은 X500 전용 시계열 예측·이상탐지 모델과 실행 가능한 전체 흐름이다.** 시뮬레이션 → 원시 기록 → 전처리 → LSTM·Transformer 미래 예측 학습 → 경보 → 독립 평가를 연결한다. 배터리·추진계통의 기존 열화 상태와 비행 중 이상을 구분해 평가하며, 같은 X500/부품의 비행 간 집계는 기존 설계 범위에서 유지한다.

**다양한 실기체에 커스터마이징 가능한 파운데이션 모델은 장기 목표다.** 다기체 데이터 수집·공통 사전학습·가중치 이전·기체별 미세조정·회사 기체 적용·기종 간 일반화 검증은 현재 필수 구현 및 완료 조건에서 제외한다. 다른 기체·모터 수를 지원하는 범용 모델이나 확장 프레임워크를 미리 구현하지 않는다.

X500의 기체·센서 설정, 전처리, 모델 코드는 기존의 단순한 경계로 분리한다. 후속 확장을 위한 빈 adapter·추상 계층·미세조정 도구를 추가하지 않는다. 새 기체 지원은 사용자의 별도 요청 후 범위와 검증 기준을 정한다.

현재의 필수 실행 검증은 X500 PX4 SITL 기준이다. 실측 X500 검증과 다른 실기체 검증은 자료·장비가 필요한 별도 단계로 표시하며, 시뮬레이션 결과를 실기체 성능이나 파운데이션 모델 완성으로 보고하지 않는다. 현재 범위 밖 작업은 `not_in_scope`로 분리하고 미완료 필수 항목에 합산하지 않는다.

## 구현 목표와 책임

PX4를 비행제어기로 유지하고 필요한 소스·메시지·설정·연결부를 수정한다. 나머지 엔진·버전·의존성은 실제 목표와 실행 검증으로 선택한다. 사용자 변경과 원자료를 보존하고 이번 요구사항에 연결되는 수정만 수행한다.

시뮬레이션은 물리·비행·센서·원시 관측·평가 정답을, AI는 원본 파싱을 포함한 모든 전처리·정상 예측 학습·경보 보정·추론·평가·비행 간 집계를 담당한다. 이번 지원 대상은 X500 기준 한 구성이다. 다른 회사 기체 적용과 기체별 모델 적응은 현재 실행 작업으로 만들지 않는다.

기본 task는 forecast다. LSTM/Transformer는 과거 history/context로 이후 센서 반응을 예측하고 실측 도착 후에 점수화한다. 학습 loss와 이상 점수는 명세의 미래 target 기준으로 계산한다.

정상 학습 자료는 주요 부품이 모두 건강한 X500의 다양한 정상 운용이다. 기본 독립 평가는 같은 X500의 `x500_run_holdout`이며 새 기체 확보를 요구하지 않는다. 건강한 저잔량/고부하/환경 변화와 열화를 혼동하지 않는다. 정상 train/validation/calibration과 독립 정상/이상 test, 기존 열화와 급성 고장을 구분한다. test를 보고 수정하면 새 최종 평가를 잠근다.

## 정보와 해석 경계

기본 공통 신호에는 개별 RPM·개별 모터 전류·모터/배터리 온도·개별 셀 전압·BAT.Res를 추가하지 않는다. simulator 내부 SOC·건강 파라미터·미래 실측은 neural forward 입력이 아니다. 건강 적격성은 데이터 선정, ID는 그룹/추적, truth는 evaluator에만 사용한다.

100시점 history, 60초 통계, segment 누적량, 필터 상태, 비행 간 추적의 기억 범위를 구분한다. 숫자·4개 target·19개 입력은 출발 실험 설정이지 검증된 최적값이 아니다. 예측오차는 원인 확정·열화율·SOH/RUL이 아니며 작은 오차도 건강 인증이 아니다.
