# v4.2 최종 검토 기록 — X500 현재 범위

문서 버전: 4.2 · 검토일: 2026-10-13

## 1. 결론과 검토 범위

현재 필수 대상은 X500 기준 한 구성이다. 건강한 X500의 다양한 정상 운용으로 LSTM·Transformer 미래 예측 모델을 학습하고, 배터리·추진계통의 이상을 독립 평가하는 범위를 유지했다. 다양한 실기체에 커스터마이징 가능한 파운데이션 모델은 장기 목표로만 명시했다.

회사 기체 이전·다기체 사전학습·기체별 미세조정·다른 모터 수 지원을 이번 필수 구현과 완료 조건에서 제외했다. 단순히 앞쪽 문구만 추가한 것이 아니라 AI 14절·입력 경로·분할·CLI·체크리스트·README·AGENTS·공통 계약을 함께 맞췄다. 상세 수정은 [04_CHANGELOG_V4_1_TO_V4_2.md](04_CHANGELOG_V4_1_TO_V4_2.md)에 있다.

**PX4 빌드, SITL, AI 학습/추론, 실제 열화 검출률, 실기체 성능 검증은 이번 작업에서 실행하지 않았다.** 이 기록은 문서·예시·패키지 검증이다. 사용자 PC·저장소의 설치/구현 완료를 판정하지 않는다.

## 2. 중요 정정

**학습 범위:** 한 기체는 한 번의 비행을 뜻하지 않는다. X500 기준 형상·추진/배터리 구성·제어 설정은 고정하고, 선언한 기동·바람·탑재량·잔량·온도의 정상 운용을 다양하게 한다. 실제 온도 등의 추가 센서값을 기본 AI 입력에 넣지는 않는다.

**독립 평가:** 기본을 `x500_run_holdout`으로 구체화했다. 같은 X500에서 독립 run을 생성하되 원본 중복·재시도·paired case는 함께 묶는다. 새 기체의 성능이라고 주장하지 않는다. 연속된 같은 자산의 이력은 `same_asset_future`의 시간 순서를 지킨다. 단 하나의 로그를 잘라 독립 시험처럼 쓰는 것은 허용하지 않는다.

**확장 경계:** 새 기체 연결·미세조정은 `not_in_scope`이며 현재 미완료 필수 항목이 아니다. X500 profile·전처리·모델·정상 보정의 기존 분리만 유지하고 범용 framework를 미리 만들지 않는다. BIN과 다른 capability 설명은 후속 참고로 남기되 필수 작업·CLI에서는 분리했다.

**검출 의미:** 예측오차는 건강 인증·고장 원인·열화율·SOH/RUL이 아니다. 짧은 예측으로 일정한 열화 상태를 놓칠 수 있으므로 pre_existing 시험은 유지했다. 별도 진단 모델은 후속 선택이며 실패를 숨기기 위한 필수 범위 확장을 하지 않는다.

**시간과 관측:** 100시점 history, 60초 문맥/segment 누적량, 미래 10시점 target, 예측 발행과 실측 도착 후 경보의 시간 의미는 바꾸지 않았다. 삭제했던 18절과 관련 학습 과제도 다시 넣지 않았다.

## 3. 실제 검증 기록

직접 원본은 대화의 `CODEX_REBUILD_PACKAGE_V4_1.zip`이다. 수정 전 기존 검사기에서 문서/manifest/ZIP 37개 검사가 통과했고, 독립 첨부한 두 주요 명세와 ZIP 내용의 바이트 일치를 직접 확인했다. 이는 원본 상태 검사이지 새 v4.2의 결과를 대신하지 않는다.

v4.2 문서 검사 43개가 통과했다. JSON/YAML 예제 26개, 요구사항 위치 68개, 직접 원본에서 보존한 핵심 구간 7개를 확인했다. 회사 기체 CLI·새 기체 기본 분할·삭제 절을 임시 사본에 다시 넣는 세 가지 검사기 자체 시험에서도 해당 오류를 검출했다. 이는 문서 검사기의 검출 시험이며 모델 성능 시험이 아니다.

v4.2는 [checks/verify_package.py](checks/verify_package.py)로 별도 검증한다. 실제 실행 결과와 시각·검사별 상태는 [checks/validation_report.json](checks/validation_report.json)에 기록했다. 보고서에는 문서/예제 검사만 기록하고, 보고서 확정 후 MANIFEST를 생성해 최종 파일 hash 및 ZIP 검사를 읽기 전용으로 실행한다.

검사 범위에는 공통 계약 세 사본, 현재 범위 블록 다섯 사본, 네 스킬 블록 여섯 사본, JSON/YAML 구문·중복 키·유한 수치, 예측/채점 예제 시각 산술, 출처·내부 링크, 현재 요구/후속 구분과 문서 위치, 삭제 과제의 비잔존, 직접 원본에서 보존한 핵심 구간을 포함한다. 문서 검사는 실제 프로그램의 기능·예측 정확도·검출 성능을 검증하지 않는다.

## 4. 보존·출처·남은 검증

원본 v4.1 ZIP·첨부 명세와 원본 v3는 그대로 남겼다. 직접 원본의 hash와 보존 구간은 [checks/baseline_provenance.json](checks/baseline_provenance.json), 현재 반영 위치는 [checks/requirements_trace.json](checks/requirements_trace.json), 새 배포 파일은 [MANIFEST.json](MANIFEST.json)으로 확인한다. 과거 v3→v4 이력은 역사 자료이며 현재 범위를 추가로 요구하지 않는다.

기존 물리·AI 참고자료의 식별자와 URL은 유지했다. 이번 변경을 위해 새 기술 논문이나 PX4/PyTorch release 호환성을 검증하지 않았다. 작업 지침 원문 접근 성공/실패는 `00_SOURCE_NOTES.md`에 구분했고, 사용자 PC의 스킬 설치·전역 설정을 변경하지 않았다.

실제 구현 담당자는 X500의 수치 물리 시험·PX4 SITL 연결·AI smoke·정상 학습·독립 탐지 평가를 실행하고 증거를 붙여야 한다. 실측 X500 또는 다른 실기체 시험을 하지 않았다면 해당 성능을 주장하지 않는다. 파운데이션 모델과 기체별 커스터마이징은 별도 후속 요청에서 범위를 정한다.
