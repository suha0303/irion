# M26–M29: 배터리 이상 시험과 로컬 AI 화면 연결

2026-11-15 KST. 원격 GPU 없이 수행했다. 기존 원본/적응 모델과 보정 기준을
고정한 뒤 X500 이상 비행을 실행했고, 사용자 지적에 따라 UI 연결과 관리 흐름을
수정했다. 이 작업은 배터리 열화 검출 성공이나 실기체 성능 검증이 아니다.

## M26 — 고정 모델로 새 이상 비행 평가

- 시나리오 `battery_aging_step`, seed `20261124`, GUI에서 180초 랜덤 임무.
  임무 시작 60초 뒤 1초 동안 `rpt_00`에서 `rpt_16`으로 전환했다.
- native run `132769b0e2484d87b040f7895a8e5f73`, 앱 기록
  `live-84510bf98fea471f`. 물리 적용은 요청보다 1 ms 늦었고 truth의 전환 비율
  0→1을 확인했다. 착륙·시동 해제·자식 종료 코드 `[0, 0]`을 확인했다.
- 실시간 경보는 중복 관측을 제외하면 **2시점**이다. 물리 이상 적용 후
  약 57.33초와 58.43초이며, 두 경보 모두 **Yaw 각속도 잔차**가 기준을 넘었다.
  표준화 전압 잔차는 각각 0.12438/0.23494로 기준 4.96953 이내였다.
- 종료 후 모델은 점수 **0.91493 < 2.45406**, **정상 범위**로 판정했다.
  전압 RMSE는 **0.28721 V**다. 배터리 열화는 놓쳤다.
- 같은 저장 로그의 독립 재분석은 205창 중 3창이 기준을 넘었다.
  수신 시작 후 20.4초(고장 전), 131.4초/132.4초(고장 후)이며 모두 Yaw 잔차다.
  실시간과 사후 분석은 예측 창 시작 시점이 다르므로 경보 수를 섞지 않는다.
- 기록 228.3946초 중 215.3초(94.2667%)를 연속 구간으로 사용했다.
  시작 9.5초와 끝 3.5946초는 필수 입력 누락/오래됨으로 제외했다. 중간 reset은 0이다.
- 이 로그는 명시적 이상 평가 자료로 등록했다. 정상 학습·보정에 사용하지 않았다.
  source SHA-256은 `315434781bb4c47a20b9037df3168bf42b0c7e25fcb7a62079a13586212c223c`다.
  이전 학습·비교·보정·정상 평가와 분리했다. 기준을 낮추거나 가중치를 수정하지 않았다.

증거는 로컬 `ai/reports/anomaly-demo-20261115/verification.json`,
`flight-result.json`, `fault-evidence.json`, `observations.jsonl`에 있다.
실시간 경보별 입력을 같은 고정 모델로 다시 계산해 당시 점수와 일치함을 확인했다.
배터리 탐지 개선은 별도 정상/이상 자료와 새로운 독립 평가가 필요한 미완료 항목이다.

## M27 — 실제 로컬 모델과 주 화면 연결

기존 모델 카드는 외부 HTTP provider의 LSTM/Transformer 연결만 읽었고,
이상 구간 탭도 그 provider 이벤트만 읽었다. 로컬 CPU 분석은 별도 패널에서
동작했으므로 카드의 ‘미연결’과 빈 이상 탭이 실제 실행 상태를 반영하지 못했다.

- `useLocalAI`로 현재 선택한 비행의 상태를 한 번 조회해 패널·카드·이상 탭이 공유한다.
  실제 선택한 예측/종료 후 모델 이름, 적응 버전, 모델별 결과를 표시한다.
  이번 시연은 LSTM 두 종류이며 Transformer를 실행한 것으로 표시하지 않는다.
- 새 실시간 작업은 도착한 미래 실측으로 판정한 경보를 `alarms.jsonl`에 저장한다.
  시점·모델·버전·기준·점수·신호별 잔차를 보존하며 정상 값으로 덮어쓰지 않는다.
- 종료 후에는 고정한 예측 모델과 종료 후 모델을 모두 평가해 전체 런을 집계한다.
  기존 `analyses`와 등록 구간 인덱스를 유지하고 `forecast_analyses`를 별도 추가했다.
- 이전 기록은 원본 해시·기체 버전·선택 모델/가중치·수신 시계·IMU/전처리 설정이 일치하는 완료 작업만
  재사용한다. 이는 ‘저장 로그 재분석’이며 과거 실시간 경보 이력을 생성하지 않는다.
- 이상 탭은 출처/모델 필터, 기준 초과 시점, 선택 시점 예측·실측·잔차,
  전체 런 사용률, 미분석 이유와 구간 상세를 표시한다.
- 종료된 실시간 판정을 ‘판정 불가’로 계속 표시하던 혼동도 제거했다.

## M29 — 검증과 배포

- AI 관련 91개 통과. 이후 실제 CPU 작업자의 경보 파일·시점 중복 방지·종료 후
  보존을 검사하는 합성 시험을 추가해 해당 파일 5개 통과(총 고유 시험 92개).
  합성 시험에만 고정 기준을 주입하며 생산 보정 파일을 수정하지 않는다.
- 백엔드 전체 **115개**, 프론트엔드 **30개** 통과. TypeScript/Vite 빌드,
  변경 Python 파일 Ruff, `git diff --check` 통과.
- 초기 백엔드 실행은 제한된 네트워크 환경에서 멈춰 중단했다. 이후 실행의
  6개 실패는 중첩 Git 체크아웃의 AI 경로 미설정이었다. 실제 `ARION_AI_ROOT`와
  `ARION_AI_PYTHON`을 지정해 전체 115개를 다시 실행해 통과했다. 실패 로그도 보존했다.
- RC15에 포함된 Python 3.10·AI·백엔드의 영향 범위 **12개** 시험도 통과했다.
- RC15 CPU doctor: Python 번들·PyTorch 2.1.2+cpu, 모델 16종, 외부 서버 없음.
- 보이는 브라우저에서 여섯 관리 메뉴, 모델 16종, 기체 초안 입력 유지,
  이상 시점 3개와 131.4초의 실제 예측·실측, 서로 다른 두 모델 판정을 확인했다.
  테스트한 셀 수 입력은 저장하지 않고 원래 4로 되돌렸다.
- 배포 내부 파일·이전 RC14·모델 보존·압축 파일 검산과 배포 런타임 시험의
  최종 결과는 `ai/releases/drone-local-ubuntu24-20261115-rc15.tar.gz.release.json`에 기록한다.
  번들 안 체크리스트는 빌드 시점 기록이며 최종 검증은 이 외부 파일과 현재 문서를 따른다.

검증 범위는 CPU 소프트웨어와 명시한 X500 시뮬레이션이다. 실물 PX4/ArduPilot
통신·ESC RPM 발행·정상/이상 탐지 정확도, Windows 배포는 별도 대기다.
종료 후 큰 저널 목록 조회 지연은 사용자 요청대로 낮은 우선순위로 유지한다.
기존 네 개발 지침의 조회본(`ai/reports/code-review-20261115/guidelines/`)을 적용했다.
