# G9 MAVLink 입력 경로 대조

기준일: 2026-11-15. 기존 모델·scaler·임계값·성공/실패 기록을 보존하고,
수집 차이를 먼저 확인한다. 비행은 16병렬, 전처리·분석은 최대 4병렬이다.
이 문서의 실험은 PX4 X500 SITL이며 실제 기체 성능 검증이 아니다.

## 확인한 원인과 남은 불확실성

G8의 같은 비행 4개에서 내부 관측과 실제 MAVLink 원문을 대조했다.
각속도 단위와 FR/FL/RR/RL 모터 매핑의 뒤바뀜은 발견하지 못했다.
빠른 내부 관측은 약 100 Hz, 기존 MAVLink 요청은 20 Hz였다.
목표 각속도는 짧은 시간에 변하며, 같은 비행에서도 수집 시점에 따라
평균과 분산이 달랐다. ATTITUDE_TARGET의 헤더 시각은 attitude setpoint의
시각이며 함께 실리는 rate setpoint의 개별 측정 시각을 뜻하지 않는다.
그러므로 모든 필드를 헤더 시각으로 옮기면 정확해진다고 가정하지 않는다.

별도 진단에서 정상 비행 2개의 **동일한 내부 원문**과 동일한 인과적 전처리,
원본 forecast_transformer_h64_l4·scaler·임계값을 유지하고 100 ms 프레임의
시작 위치만 0~90 ms, 10 ms 간격으로 바꾸었다. 0 ms에서는 두 비행 모두
경보가 없었으나 10~80 ms에서는 두 비행 모두 경보가 발생했다.
20 ms에서 점수/원본 임계값 비율은 최대 약 84배였다. 이는 해당 모델과
현재 전처리 조합의 시점 변화 취약성을 보이는 진단이며, 모든 16종에 대한
시험이나 실제 기체 오경보율 추정은 아니다.

첫 ATTITUDE의 FC 시각에 수신 프레임을 맞추는 방법도 4개 정상 비행에서
진단했지만 오경보가 남았다. 이를 제품에 적용하지 않았다. 미래 관측·고장
정답을 입력에 넣거나, 고장이 잘 잡히는 시점을 골라 배포하지 않는다.

## 이번 구현

- UDP 자동 설정에서 빠른 6종 메시지를 100 Hz로 요청한다. 공유 직렬 링크는
  대역폭이 확인되지 않아 기존 20 Hz를 유지한다. 배터리는 5 Hz다.
- 비행 상태 입력에 쓰는 EXTENDED_SYS_STATE 5 Hz를 자동 협상에 추가했다.
- ACK, 설정 조회, 실제 수신률을 별도로 기록한다. 요청한 주기와 실제 도착한
  주기가 같다고 가정하지 않는다.
- IMU 선택과 수집 정책을 준비 자료·보정·적응 모델의 입력 식별 정보에 남긴다.
  이전 20 Hz 자료와 새 설정의 자료를 학습/보정에서 섞거나, 이전 수집 설정의
  적응 모델·판정 기준을 새 연결에 적용하지 못하게 한다. 기존 자료는 보존한다.
- 실시간과 저장 분석의 수신 시계·필터·19개 입력 계산·점수·후처리는 유지한다.
  모델 재학습과 임계값 재조정은 이번 입력 수정 검증에 포함하지 않는다.

메시지 주기를 높이면 저장량과 메모리 사용도 늘어난다. 실제 SessionRun의 표시
변환·디스크 기록에 새 원문 180초, 132,352개를 2배 속도로 공급한 확인은
90.32초에 끝났고 기록 오류는 없었다. 표시 보관 60,000개 상한을 유지했으며,
최대 RSS 약 820 MiB, 기록 약 477 MB였다. API 응답 지연이나 장시간 연결
시험을 대체하지 않는다. 처음의 무제한 속도 공급은 16 MiB 쓰기 버퍼 보호에
걸렸으며 실패 기록을 보존했다. 실제 수신률에서의 실패로 해석하지 않는다.
실시간 AI의 기존 500,000개 변환 메시지/2시간 중 먼저 도달하는 한도도
유지한다. 높은 수신 주기에서는 시간 한도보다 메시지 수 한도에 먼저 도달할
수 있으며, 장시간 고주기 수집의 메모리/저장 최적화는 별도 검증이 필요하다.

## 새 16회 결과

새 seed 251115400~251115407의 정상/이상 짝 8개를 사용했다. 임무는 과거와
같은 480초, 초기 SOC 0.9·25℃·추가 탑재 0이다. random/mixed 기동과
calm/low 바람을 포함했고, 이상은 임무 300초 뒤 배터리/추진계 step/ramp로
적용했다. 수집 16개가 모두 완료됐고 자동 재시도는 없었다. native joint 검사는
16개 모두 통과했고 이상 8개는 정답 기록에서 목표 고장 파라미터 도달을 확인했다.
ATTITUDE의 실제 평균 수신률은 99.61~99.66 Hz였다. 초기 30초 이후의
5초 간격 관측에서 HEARTBEAT 외 필수 메시지는 매번 ACK·조회·수신률 조건을
통과했다. PX4의 HEARTBEAT 주기 설정은 ACK 4로 거절됐지만 기본 약 1 Hz
수신은 이어졌다. 이를 설정 성공으로 바꾸지 않았으며 전체 `all_verified`는
false다. 선택 신호 ESC_STATUS는 ACK/조회는 있었지만 실제 수신은 없었다.
분석의 19개 필수 입력에 RPM을 추정해서 추가하지 않았다. 준비된 유효 구간은
전체 수신 시간의 91.32~95.92%이며 각 비행 한 구간이다. 지상·상태 미확인
구간은 제외 이유와 함께 보존했다.

고정한 예측 모델은 `forecast_transformer_h64_l4`, 종료 후 모델은
`run_health_transformer_h64_l2`다. 가중치·scaler·원본 임계값을 변경하지 않았다.
두 모델 모두 아래와 같은 비행별 경보 수를 보였다.

| 입력 경로 | 정상 비행 경보 | 이상 비행 검출/경보 |
|---|---:|---:|
| 내부 원문·기존 전처리 | 0/8 | 8/8 |
| 새 MAVLink 전체 분석 구간 | 8/8 | 8/8 |
| MAVLink 중 내부 임무 구간만 진단 | 4/8 | 8/8 |

예측의 이상 검출은 **고장 후 새 경보 사건**이며 지연은 MAVLink 전체에서
4.87~22.82초였다. 그러나 이상 8회 모두 고장 전에도 경보가 있었다.
종료 후 모델은 런의 전압 이상 경보이며 고장 시점/부품 식별을 뜻하지 않는다.
내부 임무 구간은 평가용 정답으로 자른 사후 진단으로만 사용했고, 앱에서
이륙 직후를 숨기는 정책으로 적용하지 않았다. 임무 중 오경보 4회는 모두
random 기동이며 mixed 4회에서는 없었다.

G7의 다른 정상 수집에서 만든 보정값을 **진단 목적으로만** 교차 적용하면
두 모델·세 경로 모두 정상 경보 0/8, 이상 검출/경보 0/8이었다. 이 보정값을
새 입력에서 사용하는 것은 이번 입력 식별 검사로 차단된다. 임계값을 높여
오경보만 줄이는 방식으로는 이상 감도도 사라진다는 증거다.

이번 결과는 G8과 다른 seed이므로 7/8→8/8을 수집 주기 변경의 인과적 개선량으로
주장하지 않는다. 원본의 내부 입력 결과는 재현됐으나 실시간 입력의 성능은
복구되지 않았다. 예측·종료 후 두 모델 이외 14종의 탐지 성능을 일반화하지 않는다.
세부 수치는 `fresh16-01/comparison.json`, 원본 전체 점수는
`fresh16-01/native-vs-mavlink-mission-v2.json`에 보존한다.

## 재학습 여부의 판단 순서

입력 수정을 먼저 검증하고, 원본 모델의 정상 오경보·고장 후 새 경보·지연을
고정 임계값으로 보고한다. 입력 차이가 줄어도 성능이 회복되지 않으면 실제
수집 경로와 시점 변화, 운항 조건을 포함하는 정상 자료로 부분 적응을 비교한다.
이때 정상 오차 감소만으로 채택하지 않으며 독립 이상 탐지 퇴행을 막는다.
부분 적응으로 해결되지 않을 경우 학습 데이터 구성과 전처리의 변경을 포함한
새 모델 학습이 필요하다. 아직 전면 재학습 필요 또는 30~60분 내 성능 회복을
확정할 근거는 없다. 기존 모델은 비교 기준으로 그대로 유지한다.

`stop`으로 바꾼다. 현재 배포는 입력 수정과 검증 차단을 포함하지만 실시간
이상 탐지 성능 통과 배포가 아니다. 이전 모델·배포·운영 선택을 보존했다.
