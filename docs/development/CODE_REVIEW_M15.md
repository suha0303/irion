# M15 — 전압 예측 오차 원인 추적

2026-11-15. 실제 BIN 3개의 보존 구간 12개에 고정된 16종 모델을 다시
실행했다. **단위·셀 수 환산·출력 복원·시간 정렬의 코드 오류는 발견하지
못했다.** 학습 범위와 다른 입력 분포, 특히 모터 명령·전류에 대한 모델의
민감도가 큰 오차를 설명하는 근거다. 물리적 원인을 확정하거나 실기체
성능 문제를 해결했다고 보고하지 않는다.

모델·scaler·임계값·원시/준비 데이터·기존 평가 결과는 변경하지 않았다.
새 진단 코드와 결과만 추가했다. 건강 상태는 모두 unknown, 용도는
평가로 유지했고 파인튜닝·보정·모델 선택은 하지 않았다.

## 순서대로 배제한 가능성

1. **원시 단위**: 세 BIN의 onboard FMTU/UNIT을 직접 읽고 BAT.Volt의 V,
   BAT.Curr의 A, RCOU의 µs를 대조했다. raw adapter의 전압·전류는 원시
   V/A와 같으며 그 단계에서 셀 수나 용량을 미리 나누지 않는다.
2. **기체 정규화**: 준비 데이터는 팩 V/A, 모델 입력에서만 12셀·44 Ah로
   나눈다. 원래 학습도 X500의 4셀·12 Ah로 나눈 cell-V/C-rate다.
   이 수치는 로그 기반 프로파일이며 실물 확인을 대신하지 않는다.
3. **고정 scaler와 시간**: 모든 forecast 정답 창의 원시 프레임을 따로
   추출해 역정규화 값과 대조했다. origin 다음 0.1–1.0초 10개 정답이며
   최대 복원 차이는 셀당 약 3.1e-7 V였다. 구간을 넘는 창은 만들지 않는다.
4. **실행 환경/가중치**: 별도 보존된 정상 validation 1편을 16종 CPU로
   실행해 전달 당시 GPU 출력과 대조했다. 최대 수치 차이는 약 4.1e-6
   (작업별 출력 단위), 기존 경보 결과는 16종 모두 같았다. 수치 오차를
   새 성능 합격선으로 사용하지 않았다. 이 정상 validation의 전압 RMSE는
   모델별 셀당 0.00142–0.00211 V였다. final test를 다시 선택/튜닝하지 않았다.
5. **기존 실제 결과 재현**: 16종 × 12구간 = 192개 전체 결과가 유한하다.
   기존 분석과 팩 전압 RMSE 차이는 최대 1.8e-6 V였다. 이번 새 코드가
   과거 큰 오차를 임의로 없애거나 다른 출력으로 바꾸지 않았음을 확인했다.

학습 입력은 simulator의 출력 매핑 뒤 명령을 0–1로 변환한 값이다.
ArduPilot PWM도 명시된 최솟값/최댓값으로 0–1 변환하지만, 두 기체의 같은
숫자가 같은 추진력·전력이라는 보장은 없다. ArduPilot의 모터 출력에는
비선형 추력 보상도 있으므로, 입력 평균에 맞추거나 추력 곡선을 추측해
변환하는 처리를 추가하지 않았다.
[ArduPilot 공식 설명](https://docs.ardupilot.org/copter/docs/motor-thrust-scaling.html)

## 전체 구간의 오차

47,737프레임에 대해 forecast는 모든 예측 시점, run_health는 각 구간의
첫 10초 이후를 집계했다. 표는 3개 로그를 합친 모델별 범위다.

| 작업 | 전압 RMSE, 팩 V | 비교 기준 |
|---|---:|---|
| forecast 8종 | **0.606–0.938** | 각 예측 origin의 직전값 유지 **0.098 V** |
| run_health 8종 | **3.490–14.532** | 각 구간 초기 10초 중앙값 유지 참고치 **0.673 V** |

두 작업은 다른 문제다. run_health 참고치는 건강 판정 모델이나 채택할
대체 검출기가 아니다. 원래 건강 모델은 초기 구간 이후의 실측 전압을
가려 기준 전압을 예측하므로 입력 이전 실패의 영향이 더 클 수 있다.

forecast는 평균 편향을 사후 제거해도 centered RMSE가 0.526–0.822 V다.
일괄 전압 상수 보정만으로 해결될 문제가 아니다. run_health LSTM의
평균 편향은 약 +9.20~+14.17 V, Transformer는 -2.70~-10.15 V였다.
평균적으로 높거나 낮게 예측하는 편향이 크지만 이를 뺀 잔여 변동 오차도
2.07–3.67 V다. 평가 비행의 실측 평균을 이용해 모델 출력을 보정하지 않았다.

## 입력 분포와 민감도

12개 구간의 중앙값을 보존된 학습 scaler와 대조했다.

| 입력 | 실제 구간 중앙값 범위 | 학습 평균·표준편차 |
|---|---:|---:|
| 모터 명령 4채널 | 0.336–0.549 | 평균 약 0.559, 표준편차 약 0.0123 |
| 전류 C-rate | 0.541–0.700 | 1.957 ± 0.0441 |
| 셀 전압 | 3.715–3.990 V | 3.738 ± 0.0785 V |

각 구간의 `abs(z)` 95백분위는 모터 채널 5.7–27.9, 전류 30.9–36.1이었다.
이는 학습 scaler 기준 거리이며 가우시안 확률·이상 임계값·고장 판정이 아니다.

원인 확인용으로만 입력군을 학습 평균(정규화 0)으로 바꿔 비교했다.
실측 입력·원본 모델은 그대로 보존하고 어떤 변형도 운영 추론에 적용하지 않았다.

| 종료 후 모델 | 원래 RMSE | 모터 입력만 학습 평균으로 바꾼 실험 | 전류만 바꾼 실험 |
|---|---:|---:|---:|
| LSTM 64·2층 | 14.532 V | 1.842 V | 10.211 V |
| LSTM 128·4층 | 13.090 V | 2.251 V | 9.021 V |
| Transformer 128·2층 | 3.490 V | 3.469 V | 2.556 V |
| Transformer 128·4층 | 10.609 V | 4.597 V | 7.702 V |

여러 모델에서 모터/전류 입력에 큰 민감도가 확인됐다. 반면 forecast 8종은
모터를 평균으로 바꾼 실험에서 모두 더 나빠졌다. 따라서 특정 입력을
지우거나 평균으로 덮는 것을 해결책으로 적용하지 않는다. 상관관계가
깨지는 인위적 실험이므로 실제 물리 원인이나 수정 후 정확도의 증거는 아니다.
forecast 민감도 실험만 구간당 시간순 32개 창을 균등 표집했고, 위 전체
오차 표는 표집하지 않았다. run_health 민감도 실험은 전체 구간이다.

## 추가한 코드와 남은 일

`ai/localflight/voltage_diagnostics.py`에 읽기 전용 진단 명령을 추가했다.
팩 전압 RMSE·평균 편향·centered RMSE, 단순 유지 기준, 입력별 학습 거리,
입력군 민감도, 모델/scaler/manifest/source 해시를 새 JSON에 기록한다.
역할·건강 라벨을 변경하거나 모델을 학습/보정/등록하지 않는다.
출력 파일이 이미 있으면 거절한다. 최대 64개 패키지·72,000프레임으로 제한한다.

```bash
cd /home/sa/CapstoneV3
PYTHONPATH=ai:ai/src:Data/generation OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
ai/.venv/bin/python -B -m localflight.voltage_diagnostics \
  ai/reports/real-flight-analysis-20261114/prepared/*/manifest.json \
  --output ai/reports/voltage-diagnostics-review.json
```

새 출력 이름을 사용한다. 이 명령은 GPU 서버 없이 CPU에서 실행하며,
저장된 16종 가중치와 준비된 로그가 있는 현재 개발 환경용이다.

- **코드로 완료**: 시뮬레이션 22개 시험의 의존성 정정, 전압 단위/정렬/
  복원 검산, 재현 가능한 오차 분해·입력 민감도 진단.
- **확인한 모델 한계**: 현재 원본 16종의 이 기체 이전 성능 부족. 특히
  종료 후 모델은 모터/전류 분포 차이에 민감하다. 오차 자체는 미해결이다.
- **실물·독립 비행 필요**: 셀 수·배터리 종류·44 Ah·출력/모터 의미 대조,
  정상 근거가 있는 적응 비행과 별도 평가 비행, 정상/이상 탐지 성능.
  현재 unknown 로그를 정상으로 바꿔 파인튜닝하지 않는다.

증거: `ai/reports/failure-investigation-20261115/m15/`의
`voltage-diagnostics.json`, `summary.json`, `raw-unit-audit.json`,
`cpu-reference.json`. 최초 실험 `voltage-probe.*`도 별도로 보존했다.
기존 결과를 교체하지 않고 이번 진단으로 연결한다.
