## M6 — 공개 인터페이스

45개 파일에서 운영 모듈 7개·주요 클래스 57개의 설명을 보강하고, 공개
함수·메서드 18곳에 타입과 입력·반환·오류 계약을 명시했다. 특히 다음을
코드에서 바로 확인할 수 있도록 했다.

- 프로파일의 선택 정보와 분석 적격성은 다르며, 채널은 1부터 시작하고
  용량은 Ah를 사용한다. 모르는 기체 스펙은 문서 보강으로 추정하지 않는다.
- forecast 입력은 FP32 `[batch, 100, 19]`, 출력은 `[batch, 10, 4]`다.
  run-health는 완료된 연속 구간 `[1, time, 19]`와 정확한 int64 길이를 받고
  `[1, time]` 전압 기준을 반환한다. 모델 출력은 정규화 단위다.
- 전체 런 분석은 같은 비행·기체의 중복 없는 패키지 1–64개, 총 72,000
  프레임까지 받는다. 결과 시각은 마이크로초이며 사용하지 못한 구간도
  요약에 남는다. 독립 비행 비교는 탐지 성능 인증을 뜻하지 않는다.
- CPU 스레드 설정은 프로세스 전체에 영향을 주고, 모델·저장소·캐시는
  각각 어느 객체가 소유하는지 명시했다.

문서·타입·import를 제외한 실행 AST는 45개 파일 모두 동일했다. 구문 컴파일,
Ruff 검사·333개 파일 포맷 검사, 실기체 분석 관련 **64개 시험**, UI 백엔드
전체 **92개 시험**이 통과했다. 계산·기존 데이터 키·API 필드는 바꾸지 않았다.
변경하지 않은 프런트엔드와 전체 Data 검사는 이 단계에서 반복하지 않았다.

[최신 파일 목록](CODE_REVIEW_FOLLOWUP_INVENTORY.json)은 현재 551개 파일과
