# G7 정상 비행 초반 예측오차 추적

2026-11-15. 기존 모델과 정상 20회·이상 4회 결과를 보존하고 입력 경계만 먼저 수정했다.
새 비행 검증을 완료했지만 이상 탐지 성능은 미통과다. 소프트웨어 수정 완료와 구분한다.

## 원인과 수정 범위

1. 기존 최종 모델은 100시점 입력 이력 전체가 airborne인 창을 사용한다. 최종 데이터 인수는
   실제 mission 구간 안의 이력/미래 실측만 허용한다. 로컬 MAVLink 경로에는 이에 대응하는
   운용 상태 제한이 없어 지상·이륙 전환 구간이 처음 예측 이력에 들어갔다.
2. 이전 정상 20회에서 첫 예측 시각은 평균 수신 후 21.55초였다. 일부 초기 이력의
   climb_rate_error는 학습 표준편차의 315–331배, specific_force_z는 76–79배였다.
   단위 변환이나 0으로 초기화한 필터 때문이라는 근거는 없었다. 기존 LowPass는 실제
   첫 관측값으로 초기화한다. 신호를 잘라내거나 정상값으로 대체하지 않았다.
3. 이전 정상 20회의 동일 예측 중 FC가 비행 중이라고 확인한 이력/목표만 비교하면 첫
   세 예측의 평균 정규화 RMSE는 p/q/r/전압 순서로
   `1.926/1.935/3.997/0.446 → 1.009/1.664/2.223/0.265`였다.
   이는 기존 정상 데이터의 원인 진단이며 새 평가 성능이 아니다.
4. 별도 결함: ULog의 arming/landed/nav 상태도 빠른 센서의 200ms 갱신 기준으로 처리했다.
   1Hz 상태가 도착할 때 연속 신호와 필터를 초기화했다. 동일 합성 관측을 실제 이전 코드와
   비교했을 때 불필요한 경계 39→0개, 완전한 시점 361→400개, 11초 이상 구간 0→1개로
   수정됐다. MAVLink 이전 경로는 상태를 아예 버렸으므로 이 결함의 영향을 받지 않았다.

`fc-confirmed-airborne-history/1`은 새로운 자료에 적용한다.
MAVLink HEARTBEAT의 armed와 EXTENDED_SYS_STATE의 IN_AIR, ULog의 arming_state/landed를
인과적으로 읽는다. arming은 1.5초, landed는 2.5초 이내의 관측이어야 한다. 상태
미관측·지상·명시적인 이륙/착륙은 모델 입력 구간에서 제외하고 이유를 남긴다.
100시점 이력과 도착한 미래 10시점이 경계를 넘지 않는다. 연속 신호의 원값·필터·scaler·
기존 모델과 점수 계산/EWMA/지속 조건은 변경하지 않았다.

상태 enum의 근거는 [MAVLink 공통 메시지 정의](https://mavlink.io/en/messages/common.html#MAV_LANDED_STATE)와
프로젝트가 고정한 PX4 common mapper다. 상태는 고도·전압·경과 시간으로 추정하지 않는다.
상태 필드는 연속 신호와 별도로 갱신하므로 낮은 상태 메시지 주기가 센서 필터를 초기화하지 않는다.

ULog와 MAVLink 신규 준비 자료에는 정책을 기록하고 보정값의 결합 조건에도 포함한다.
이전 보정값을 신규 자료에 자동으로 재사용하지 않는다. 다른 준비 정책의 비행을 학습·개발·
보정·평가 역할에 섞으면 거절한다. 이전 파일은 그대로 읽어 당시 결과를 재현할 수 있다.
ArduPilot BIN의 기존 검토된 airborne 구간 선정 경로는 보존한다. 실시간 ArduPilot에는
동일 MAVLink 상태 관측이 필요하며 실제 기체의 제공 여부는 검증 대기다.

## 남는 운용 범위 차이

PX4가 IN_AIR라고 보고한 순간에도 아직 상승/초기 자세 전환 중일 수 있다.
이전 정상 비행에서 상태 전환은 수신 약 13초, 실제 상승 과도 구간은 그 뒤에도 이어졌다.
따라서 이번 비행 상태 확인을 ‘이륙 과도가 모두 끝났다’고 해석하면 안 된다.
실제 mission 경계를 사용하는 진단에서는 오차가 더 낮았지만 이 경계는 시뮬레이터
내부 실행 정보다. 실기체 입력에 이를 몰래 사용하거나, 일정 시간을 임의로 추가 제외하거나,
큰 잔차를 보고 구간을 삭제하지 않았다. 비행 중 큰 전압/각속도 변화도 그대로 보존하는
회귀 시험을 추가했다. 초기 비행 구간의 이상은 이력 준비 전 판정할 수 없다.

## 새 검증 절차와 보존

새 seed 251115200–251115223을 사전 고정했다. X500 PX4 실제 SITL을 4개 독립 인스턴스로
각 mission 180초씩 수행하며 실제 MAVLink 수신 시각을 사용한다.
정상 20회는 학습 3·개발 3·보정 8·평가 6회로 구분한다. 독립 이상 4회는 배터리 급변/점진,
추진 급변/점진이며 고장은 mission 시작 60초 뒤 적용한다.
가장 좋은 원본 forecast Transformer h64/l4와 종료 후 Transformer h64/l2를 각각 시험한다.
후보는 이전과 동일한 30 epoch/최대 3600초 설정, CPU 복원 확인과 비열화 평가를 거친다.
고장 정답으로 임계값을 맞추지 않으며 후보 자동 적용은 하지 않는다.

동일한 새 정상 원본에 이전 전체 구간 준비와 수정한 비행 상태 준비를 각각 적용한다.
동일 시각에서 남은 물리 입력은 정확히 같아야 한다. 첫 세 유효 예측과 전체 구간의 실제
단위 오차, 정상 오경보, 고장 이후 해당 영역 검출, 실시간 도착/파일 점수 일치를 따로 보고한다.
서로 다른 시작 시각/커버리지를 표시하여 예측 모델 자체의 개선과 구간 제한 효과를 혼동하지 않는다.

원본 16종 model/scaler/calibration, 이전 회차 원본·준비 자료·후보·평가 파일 419개를
`ai/reports/startup-audit-20261115/preservation-seal.json`에 봉인했다.
새 AI 코드와 수집/평가 방법은 `pre-collection-seal-03.json`으로 고정했다.
첫 두 수집 시도는 Python/의존성 불일치로 PX4 시작 전에 종료됐다. 모든 실패를 보존하고,
기존 `simulation/.venv` Python 3.12.3에서 같은 seed로 실행했다. 환경 설치나 변경은 없었다.

## 시험과 새 결과

- 입력 경계/실시간/로그/보정 관련 28개 통과. 합성 송신기의 초기 armed 조건을 수정한
  첫 실패 기록도 보존했다.
- 로컬 AI 전체 119개 통과. 추가한 ‘비행 중 큰 변화 보존’ 포함 운용 상태 6개 통과.
  전체 런 미관측 상태의 기대 사유를 새 정책에 맞춘 이전 실패도 남겼다.
- UI 36개, TypeScript/Vite 빌드 통과. 기존 번들 크기 경고는 유지한다.
- 백엔드 전체 113개 통과/2개 실패 후, 원인인 시험 송신기의 고정 8개 메시지 잘라내기를
  동일 시각 메시지 묶음으로 바꿨다. HEARTBEAT 누락 없이 실시간 관련 4개 재시험 통과.
- RC19 빌드·doctor: 16종 CPU 실행 통과. 새 비행/평가를 앱에 가져오고 브라우저로 확인했다.

중복을 제외한 시험 수는 AI 120개, UI 36개, 백엔드 115개다. 전체 실행 및 수정 후 영향
범위 재시험을 합한 수이며, 단일 실행에서 모두 통과했다고 표현하지 않는다.

24개 비행은 모두 native/수신기 종료 코드 0으로 완료했다. 사용률은 78.25–81.18%,
실제 사용 시점은 44,099개(4,409.9초)다. 운용 상태 제외를 추가해 전체 기록 사용률은 감소했다.

양쪽 모델의 기준은 각각 별도 정상 개발/보정 자료로 만들었다. ‘원본’은 가중치가 원본이라는
뜻이며 과거 최종 평가의 원본 임계값을 복사했다는 뜻이 아니다. 새 후보는 둘 다 거절했고
앱의 모델/보정 선택 파일은 변경되지 않았다. GPU 적응 두 모델 전체 21.879초,
배포 Python 3.10/PyTorch 2.1.2 CPU 복원 통과. 모델을 늘리거나 더 오래 돌리면 검출이
회복된다는 근거는 없다.

동일한 정상 평가 6개에서 원본의 첫 세 예측 RMSE 평균은 p/q/r/팩 전압 순서로
`0.03510/0.03263/0.18966/0.16851 → 0.02919/0.02902/0.15909/0.13399`였다.
전압은 20.5% 줄었지만, 이 효과는 비행 상태 경계 수정이며 가중치 개선이 아니다.
전체 구간 pitch RMSE는 증가했고 오경보도 이전 경로 2/6→수정 경로 3/6으로 증가했다.
후보의 초기 전압 RMSE도 원본 0.13399→0.13553 V로 나빠졌다. 전체 평균 전압 RMSE
0.05641→0.04892 V의 개선만으로 후보를 통과시키지 않았다.

실시간 도착/파일 경로 3,464개 블록의 점수와 경보가 정확히 일치했다. 실제 CPU 배포와
GPU 환경의 CPU 추론을 대조한 40건도 판정/경보/에피소드가 일치했고 최대 점수 차이는
4.84e-7이었다. 모델 수치의 bit 단위 일치라는 뜻은 아니다.

증거는 `ai/reports/startup-audit-20261115/summary.json`, `paired-startup-comparison.json`,
`cpu-delivery-parity.json`, `ui-import.json`에 있다. RC19 압축 SHA-256은
