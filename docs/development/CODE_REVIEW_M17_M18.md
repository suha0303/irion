# M17–M18: 데이터 이관과 Ubuntu RC13

기준일: 2026-11-15. 기존 모델·데이터·실패 증거를 유지한 후속 작업이다.
최신 실행 안내는 [Ubuntu 실행](../ai/LOCAL_DESKTOP_UBUNTU.md), 상태 관리는
[실기체 체크리스트](../ai/LOCAL_REAL_FLIGHT_CHECKLIST.md)를 따른다.

## M17 — 구현과 보존 경계

- `drone-local migrate-data`는 중지된 최신 파일 저장 형식의 `ARION_DATA_DIR`를
  새 폴더에 복사한다. 원본·원시 기록·프로파일·준비 배열·모델·scaler·임계값·
  체크포인트·출처/바인딩 해시를 유지하고 운영용 절대경로만 변경한다.
- 변경 전 메타데이터와 파일별 SHA-256을 `.migrations/`에 보존한다. 복사 중
  원본 변경이나 검증 실패는 미완료로 남기며 앱이 해당 복사본을 열지 못한다.
- 새 앱의 데이터 잠금과 구형 서버 기록의 살아 있는 PID 확인으로 실행 중
  이관을 거절한다. PID에는 종료 신호를 보내지 않는다. 구형 앱의 직접 실행처럼
  잠금/서버 기록이 없는 경우까지 감지한다고 보장하지 않으므로 먼저 종료한다.
- 기존 대상 폴더·중첩 경로·심볼릭 링크·외부 운영 참조·변환되지 않은 SQLite를
  자동 합치지 않는다. 현재 데이터 전체가 한 폴더에 있는 형식만 지원한다.
- 다른 설치 경로/데이터 폴더의 앱이 같은 포트에 응답하면 `start/status`는
  다른 앱임을 표시한다. 설치 식별은 설치 경로와 실행 Python 경로 기준이다.
- 이관 후 로그 재생·기체별 분석·모델 ZIP·보정값 적용·중단된 적응 재개를
  합성 자료로 검증했다. 재개 모델과 중단 없는 학습의 가중치 SHA-256이 같다.
  분석 결과는 실행 시간 외 모든 필드가 같다. 원래 폴더를 숨긴 상태에서 확인했다.

## M18 — 배포 의존성 수정

첫 RC13 후보의 배포 백엔드는 100 통과·6 실패였다. `localflight.prepared` →
`execution.prepare` → `execution.common`의 import가 배포하지 않는 `console`
모듈에 의존해 워커 시작이 실패했다. 개발 소스가 있는 환경만 검사하면 숨겨지는
문제였다. `console.profile`은 원격 프로파일을 실제로 읽을 때만 가져오도록
옮겼고, 배포에 포함되는 소스만 별도 폴더에 복사한 프로세스 시험을 추가했다.
`doctor`에도 실제 워커/데이터 이관 진입점 import 검사를 추가했다.
함수 내부 import는 선택적 원격 기능과 독립 CPU 배포의 경계를 위한 유지 사항이다.

RC13은 검증한 후보2와 같은 실행 코드·모델·런타임을 사용한다. 문서 포함 목록과
안내만 추가했다. 최종 압축 해제본의 검증/해시는 배포 옆의 `.release.json`과
`.sha256`에 기록한다. 후보의 검사 결과는 아래에 기록한다. 최초 후보·실패 로그는
`ai/reports/release-rc13-20261115/`와 별도 후보 폴더에 그대로 보존한다.

## 검증 기록

- UI 포맷, 26개 시험, TypeScript/Vite 빌드 통과. 기존 3D/메인 청크 크기 경고 유지.
- 원격 프로파일 import 변경 영향의 AI 실행/콘솔/배포 85개 통과.
- 수정된 배포 Python의 실기체 AI·단위·전압 진단 101개 통과.
- 배포 Python의 UI 백엔드 106개 통과(144.78초). 외부 Starlette 시험 도구의
  deprecation 경고 1개는 유지하며 운영 실패가 아니다.
- 개발 원본 경로와 외부 네트워크를 숨긴 후보2의 16종 CPU forward, 워커 모델 API,
  프로파일 저장·이관·재조회, HTML 응답, 다른 데이터/동시 사용 차단, 기동·종료 통과.
- 기존 보호 자료 29,427개 SHA-256 동일. RC12 압축 파일 SHA-256도 그대로다.
- 합성 ULog 256 MiB 입력 검사: CPU affinity 1개, 주소공간 1.5 GiB 제한에서
  0.512초, 최대 RSS 295,396 KiB(약 288.5 MiB). 유효한 로그 메시지로 크기를
  채운 입력이다. 고밀도 센서·긴 비행·최소 하드웨어 검증으로 확대하지 않는다.
- M17 최초 분석 비교 실패는 측정 시간 비교였고, 후속 적응 재개 실패는 이미
  완료한 1 epoch를 재개하려던 시험 입력이었다. 실행 시간은 비교에서 제외하고
  실제 2 epoch 중 1 epoch 후 중단한 체크포인트로 고쳤다. 제품의 재개 조건은 유지했다.

|---|---|---|
| 검증 대기 | 실제 PX4 ULog의 필드·단위·자동 입력 | 실제 로그와 펌웨어/배터리/출력 설정 |
| 검증 대기 | 실물 FC의 19개 입력, USB/무선, 재시동·시계·종료 | PX4 우선 실물 FC/통신 장비 |
| 성능 미해결 | 전압 예측과 정상/이상 판정·적응 효과 | 건강 근거가 있는 독립 정상/이상 비행; 기존 unknown 3개를 정상으로 바꾸지 않음 |
| 배포 검증 대기 | 다른 PC/새 Ubuntu, 실제 큰 로그, 최소 사양 | 별도 환경과 대표적인 고밀도 로그 |
| 원인 미확정 | 간헐 BIN 파서 예외 | 과거 요약 오류만 있고 전체 traceback 없음; 12회 비교에서 미재현. 기본 Python 인덱서 유지, 재현 시 원본 해시·환경·전체 traceback 필요 |
| 미구현·환경 필요 | Windows 패키지와 Windows 실행 | Windows 빌드/시험 환경; Ubuntu 바이너리는 Windows용으로 재명명하지 않음 |
| 미구현·관측 필요 | 전송 지연 자동 분리 추정 | 송수신 시계 관계/동기화 관측; 수신 시간만으로 지연과 시계 오프셋을 유일하게 분리할 수 없음 |
| 미구현·형식 확장 | ULog 복수 부팅 자동 복구 | 실제 손상/부팅 경계 예시와 복구 가능한 메시지; 기존 보존 구간/수동 조정 사용 |
| 미구현·모델 확장 | 4로터 외 AI 모델 | 해당 입력 계약·학습 데이터·새 모델 및 독립 검증; 4~8로터 시뮬레이션 지원과 다름 |

기존 전압 진단 결과를 보정 계수로 억지로 맞추지 않는다. 기능 시험 통과는 실기체
정확도 통과를 뜻하지 않으며 기존 BIN 3개의 건강 상태는 unknown이다.


## 최종 배포 확인

- `ai/releases/drone-local-ubuntu24-20261115-rc13.tar.gz`, 309,023,793 bytes.
- SHA-256: `7180e34f721b66e21428f73e45e61927a400105fa89a7fcfd79820d3405c8fbf`.
- 최종 압축 해제본도 프로젝트/외부 네트워크 격리에서 doctor 16종, UI/워커 API,
  프로파일 이관, 서로 다른 데이터/동시 접근 거절, 기동·종료를 통과했다.
- 후보2 대비 실행 모듈·모델·Python 런타임 해시가 같다. 변경 파일은 문서 3개와
  그 문서를 포함하는 배포 빌더뿐이다. 빌더의 doctor/main AST도 동일하다.
- 최신 Python Ruff/check/format 339개 통과. 기존 사용자 8765 서버 인스턴스 유지.
- 이번 기능 소스는 `ef2d3f4`, 배포 수정은 `5748c04`로 분리했다.

최종 해시/증거는 압축 외부의 `.sha256`·`.release.json`에도 제공한다. 패키지 내부
문서는 패키징 시점의 후보 검사 기록이며 위 압축 후 기록으로 기존 번들을 덮어쓰지 않는다.
