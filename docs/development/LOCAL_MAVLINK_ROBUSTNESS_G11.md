# G11 MAVLink 응답 복구·수신 변형 학습·새 비행 검증

2026-11-15. **설정 응답 누락 복구는 검증했으나, 실제 수신 경로의 이상 탐지
성능은 미통과다. 두 파인튜닝 후보의 적용을 거절했고 기존 운영 선택을 유지한다.**
PX4 X500 SITL의 실제 UDP 수신 시험이다. 실물 기체·직렬 링크·RTX 3050 검증과 구분한다.

같은 새 비행 16회를 기존 내부 입력/임무 구간/원본 모델/과거 기준으로 평가하면
정상 오경보 0/8·이상 검출 8/8을 다시 재현한다. 원본 가중치나 물리 모델이
훼손됐다는 증거는 없다. 수신 시점·누락에 따른 상태 초기화·포함 구간이 달라진
MAVLink 경로로 과거 성능을 그대로 이전할 수 없었던 것이 핵심 문제다.
이번 부분 학습은 예측 오차를 줄였지만 그 차이를 충분히 해결하지 못했다.

## 응답 누락 복구

SET_MESSAGE_INTERVAL의 ACK에는 설정 대상 메시지 ID가 없다. 기존 코드는 한 번
누락되면 뒤의 필수 IMU 설정까지 중단했다. 수정은 같은 설정을 최대 3번 시도하고,
메시지 ID가 일치하는 MESSAGE_INTERVAL 조회로 확인한다. 첫 SET ACK 누락 이후
이 세션의 다른 SET ACK는 어느 설정에 대한 것인지 단정하지 않는다. 늦은 ACK가
다음 메시지를 성공/실패로 오인하게 하지 않는다. 조회도 확인하지 못하면 불완전
상태를 유지한다. 실제 수신률·기체/peer/인스턴스 확인은 별도이며 모두 유지한다.
UI는 `주기·수신 확인 · ACK 미확인`을 ACK 성공과 구분한다.

새 48회에서 ACK 누락 6건을 복구했다. 정상 수집의 ESC_STATUS 1건,
EXTENDED_SYS_STATE 2건, ATTITUDE 1건과 평가 수집의 HEARTBEAT/ESC_STATUS 각 1건이다.
정상 4건은 2초 대기 동안 디코딩 저널에 해당 ACK가 없었고 이후 조회가 요청한
주기를 반환함을 확인했다. FC 송신·소켓·디코딩 이전 중 정확한 손실 위치는 미확정이다.
PX4의 고정 HEARTBEAT 주기 설정 거부와 실제 HEARTBEAT 수신도 구분한다.

[MAVLink 명령 프로토콜](https://mavlink.io/en/services/command.html)의 재전송/응답 원칙과
현재 PX4 수신·송신 코드를 검토했다. 비행 명령·물리 모델·생산자 계약은 바꾸지 않았다.

## 학습과 자료 분리

- 원본 최상위 `forecast_transformer_h64_l4`, `run_health_transformer_h64_l2`에서 시작.
- 처음 2 epoch는 출력층, 이후 마지막 내부 층과 출력층. SGD .001→.0001,
  원본 가중치 anchor 1, 최대 200 epoch/patience 20. 기존 scaler 고정.
- 새 정상 학습 8회에 원본과 7개 수신 변형을 사용했다. 위상 10/30/50/70/90 ms,
  순서가 유지되는 0~20 ms 지연과 수신 묶음 100개당 1개 누락,
  별도 60초마다 350 ms 공백을 학습 전에 고정했다.
- 같은 비행의 변형을 독립 비행으로 세지 않는다. 비행→변형→구간 순으로 가중치를
  배분하며 예측은 총 3,000개 창 이내로 비행/변형별 균형을 맞추고 처음/끝 창을 보존한다.
- 긴 공백·미관측값을 보간하지 않는다. 지연/누락 변형은 14~20개, 공백 추가 변형은
  15~21개 구간으로 나뉘었다. 기존 200/350 ms 유효시간과 11초 최소 구간을 유지했다.
- 개발 4회·보정 20회는 변형하지 않았으며 학습 자료와 원본 단위로 분리했다.
  건강 기준은 기존 rank `ceil((N+1)*.95)`로 N=20의 20번째 값이다.
  예측도 기존 정상 전용 백분위 후보/시간당 경보 규칙을 그대로 쓴다.
- 새 8회의 모든 변형에서 최대 각속도 오차 입력은 0.30 rad/s 이하였으나, G10에서
  이미 확인한 정상 착륙 사례는 3.84 rad/s였다. 건강 학습 전에 이 정상 1회를 추가했다.
  G10 원문/기존 development manifest는 수정하지 않고 별도 역할 이력과 출처를 기록했다.
  예측은 동일 8회로 158 epoch 체크포인트를 재개했고 건강만 9회/72개 view를 썼다.
  이 변경은 건강 학습·보정·최종 비행 수집 전에 `protocol-amendment.json`으로 고정했다.
- 학습/CPU 복원 합계 1,070.08초(약 17분 50초). 예측 200 epoch 중 200,
  건강 200 epoch 중 197을 정상 개발 손실로 선택했다. 데이터 준비·비행 시간은 별도다.
  GPU는 RTX 4060 Laptop, 학습 PyTorch 2.5.1+cu121, 별도 CPU 복원은 2.1.2+cpu.

UI의 기존 1~3회 파인튜닝 흐름은 유지한다. 이번 8/9회 수신 변형 학습은 실험 실행기로
수행했다. 그룹 학습 API의 최대 원본 수는 20회지만 창/시간 상한이 있으며, 수신 변형의
자동 생성·역할 배정까지 일반 UI에 연결한 것은 아니다. 실제 미확인 건강 로그도 쓰지 않았다.

## 새 독립 평가 결과

각 행의 오경보는 정상 8회 중 경보가 난 비행 수다. 예측 검출은 고장 발생 후
**새 전체 경보 사건**이며, 고장 전 경보는 검출로 세지 않는다. 건강 모델의 배터리
검출 분모는 4건이고 추진계 4건은 해당 없음이다. 평균 오차 감소와 검출 성능을 구분한다.

| 입력/기준 | 예측 원본 오경보·검출 | 예측 후보 오경보·검출 | 건강 원본 오경보·검출 | 건강 후보 오경보·검출 |
|---|---|---|---|---|
| 기존 내부 입력·과거 기준 | 0/8 · 8/8 | 진단 대상 아님 | 이번 추가 대조 대상 아님 | 진단 대상 아님 |
| MAVLink 원문·과거 기준 | 8/8 · 7/8 | 4/8 · 7/8 | 8/8 · 4/4 | 6/8 · 4/4 |
| MAVLink 원문·정상 전용 보정 | 0/8 · 0/8 | 0/8 · 0/8 | 6/8 · 4/4 | 6/8 · 4/4 |

| 지연+1% 누락·정상 보정 | 0/8 · 0/8 | 0/8 · 0/8 | 8/8 · 4/4 | 8/8 · 4/4 |
| 지연+누락+350 ms 공백·정상 보정 | 0/8 · 0/8 | 0/8 · 0/8 | 8/8 · 4/4 | 8/8 · 4/4 |

과거 기준을 후보에 적용한 행은 진단용이다. 원문/스트레스마다 기준을 다시 맞추지 않았다.
스트레스 48개 view는 **같은 독립 16회**의 변형이며 비행 수를 64회로 늘려 세지 않는다.
원문/과거 기준의 예측 고장 전 경보는 원본 8/8, 후보 4/8이었다.

새 정상 원문의 평균 RMSE는 p/q/r 각각 27.05/40.48/41.65%, pack 전압 16.81% 감소했다.
전압은 0.031956→0.026585 V. 건강 모델의 비행별 표본 가중 RMS 평균은
0.015315→0.006995 V/cell로 54.32% 감소했다. 그래도 탐지 목표는 미통과다.

기존 적용 검사에서 예측은 `known_anomaly_still_missed`, `normal_prediction_regression`,
건강은 `normal_false_alarm_regression`으로 거절됐다. 스트레스에도 같은 검사 규칙을
각각 적용하면 두 모델 모두 거절이며 건강에 구간별 예측 퇴행 사유도 추가된다.
기본 검사는 별도로 보존했고, UI에는 스트레스까지 포함한 거절 결과를 제공한다.

## 누락/전환에 대한 추가 추적

정상 flight-03/05/07/09/13의 구간 경계에서 배터리 수신 간격이 각각
385.412/374.315/380.352/372.712/356.037 ms였다. 현재 350 ms 유효시간을 넘어
필터/이력이 초기화되고 건강 모델이 새 구간으로 시작했다. 그 다섯 비행은 재시작한
구간에서 원본·후보 모두 경보가 났다. 두 비행은 100 ms 그리드에도 결측이 드러났고,
세 비행은 그리드 사이 유효시간 초과로 경계가 생겼다. 유효시간이나 경계를 사후에
늘리거나 합쳐서 결과를 바꾸지 않았다. 이 연관은 재시작 처리의 추가 대조 근거이며
모든 오경보가 이 원인 하나로 설명된다는 주장은 아니다.

학습에 포함한 이전 정상 착륙의 마지막 실제 전압은 3.61353 V/cell이다.
원본 12.18549→후보 9.98600 V/cell, 절대 오차 8.57195→6.37247로 여전히 크다.
학습 사례에서도 충분히 복원하지 못한다. 변형을 하지 않은 재생은 이전 5,257프레임의
값·시각과 정확히 같았고, 원본 급변을 삭제하거나 출력 clipping을 하지 않았다.

## 검증 증거와 보존

원문/모델/실행기/실패 기록: `ai/reports/mavlink-robustness-20261115/`.

- `protocol.json`, `augmentation-recipe.json`, `protocol-amendment.json`, `candidate-seal.json`:
  역할 분리·학습 조건·보완 시점·최종 수집 전 봉인.
- `comparison.json`, `stress-comparison.json`, `native-baseline.json`, `summary.json`:
  원문·수신 변형·기존 내부 입력의 결과와 분모.
- `normal-restart-source-trace.json`, `normal-health-segment-diagnostic.json`,
  `landing-training-diagnostic.json`: 수신 간격·구간 경보·착륙 오차 추적.
- `evaluation-result.json`, `evaluation-result-with-stress.json`: 기본/확장 적용 검사.
  보정값 재계산은 수집 전 값과 정확히 같고, 기준을 조정하지 않았다.
- 저장/실시간은 원문 64경로·32,576블록, 스트레스 192경로·63,024블록에서
  점수와 경보가 정확히 같다. 별도 구현 차이로 실패를 설명할 수 없다.
- 첫 ACK 누락 회귀시험의 실패와 수정 후 7개 통과, AI 126개·백엔드 119개·UI 36개
  범위의 시험 기록을 보존한다. 초기 백엔드 시험의 AI 경로 누락 6건은 환경을
  명시한 재검사로 해결했으며 첫 실패도 남겼다. 최종 배포 시험 결과는 별도 로그에 기록한다.
- 최종 재검산에서도 기존 14,094개 파일이 모두 동일하다. 후보 봉인 332개 중
  331개는 기존 경로, 배포 문서 목록만 바꾼 1개는 보존한 원문 경로로 동일 확인했다. 수집 후 읽기 쉽게 정리한 백엔드 3개 파일은
  수집 당시 소스와 AST가 동일하고 이전 소스를 `acquisition-source/`에 보존한다.
- 평가 후 배포 문서 목록에 G10/G11 보고서만 추가했다. 봉인 당시 packager도
  `packaging-source-before/`에 보존했다. 모델/입력/손실/점수/판정 코드는 변경하지 않았다.

## 배포에서 발견한 목록 지연

기존 RC21에서 `/api/runs`가 20초 안에 응답하지 않았다. 종료한 수신 로그 7개를
목록마다 2개짜리 재생 캐시로 다시 읽던 경로를 확인했다. 종료 시 저장한 요약의
run ID·원문 해시·종료 상태가 카탈로그와 일치하면 목록은 그 요약을 사용한다.
진행 중인 비행과 후처리가 남을 수 있는 normalized 기록은 기존 경로를 유지한다.
요약이 없거나 손상됐거나 해시가 다르면 원래 로더로 돌아간다. 분석을 열 때의
원문 검사는 생략하지 않는다. 관련 스트리밍/NPZ/목록 회귀 49개가 통과했다.
RC23 실제 HTTP 확인에서 같은 목록 7개가 0.024초에 반환됐고 상태·작업 결과·
시작 페이지도 응답했다. G11 작업 `1f4801924dac458589902ae6979621bd`의 두 후보는
거절 상태이며 운영 모델/보정 선택 해시가 이전과 같다.

평가에 사용한 소스와 RC22 초안은 보존했다. 이 목록 개선을 포함하는 최종 배포는
RC23이다. 탐지 모델·입력 정책·점수·임계값에는 추가 변경이 없다.
