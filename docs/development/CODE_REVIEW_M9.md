# M9 — 남은 진단의 코드별 검토

2026-11-15. 기준 커밋 `43f495d`. 현재 코드의 Pylint 진단은 **1,471 → 1,318개**,
보존 소스는 **2,484개 그대로**다. 합계는 3,802개이며 오류 수준 진단은
59 → 57개다. Google pylintrc와 진단 활성화 정책은 바꾸지 않았다.

75개 현재 소스·시험 파일을 수정했다. 보존 파일 178개와 최신 모델·scaler·
임계값·계약·과거 증거는 그대로다. 수정 가능한 Python 333개의 Ruff 검사와
포맷 검사가 통과했다. 모든 Google 규칙을 충족했다는 뜻은 아니다.

## 정리한 코드

- 표준 라이브러리 등 17개 import를 옮기거나 중복 제거하고, 조건부 경로에
  남았던 표준 라이브러리 중복 2개도 제거했다. 플랫폼 의존 import는 유지했다.
- CLI 진입부 변수 16개와 함수 안의 일반 변수, 시험 이름/변수를 구체화했다.
  부모·프레임워크 호출 서명은 유지했다. 외부 이름 재정의 진단은 253 → 203개다.
- 미사용 가변 인수 이름 39개, 불필요한 기본 fixture 인수 8개, FastAPI
  콜백 인수 3개를 정리했다. 미사용 인수 진단은 217 → 167개다.
  다른 시험이 주입하는 `layout` fixture 4곳은 준비·정리 동작 때문에 유지한다.
- NumPy 배열의 빈 상태 검사 10곳을 `len(array) == 0`으로 명시했다.
  배열 자체의 truth value를 평가하지 않으며 계산·신선도·판정 기준은 동일하다.
- 권한 확인의 부수 효과를 삼항식 대신 if/else로 나타냈다. 중복된 지역 함수
  이름 2곳을 나누고, 즉시 사용하는 루프 값/점수 입력을 명시적으로 전달했다.
- 배포 메타데이터 정리에서 `Distribution._path` 접근을 없앴다. 복사된
  `.dist-info`/`.egg-info` 디렉터리를 직접 열거하고 공개 `Distribution.at`
  경로를 사용한다. 대체한 패키지의 이전 메타데이터만 제거하며 원본 overlay와
  패키지 코드는 유지한다. 링크·불완전한 메타데이터는 명시적으로 거부한다.
- UI의 주기 설정 요청 기록은 `SessionRun.record_message_rate_request`로
  옮겨 세션 잠금·종료 상태 확인·저널 쓰기를 한 곳에서 수행한다.
  정규화 프레임의 epoch는 기존 공개 `epoch_at`으로 얻는다. 운영 코드의
  비공개 멤버 접근 6개가 없어졌으며 남은 20개는 검증용 시험이다.

Python 메타데이터 경계는 [공식 Python 3.10 문서](https://docs.python.org/3.10/library/importlib.metadata.html#distributions)와
실제 `ai/.venv`의 `Distribution.at` 구현을 확인했다. 기존 RC12 압축 파일을
재생성하거나 배포한 결과가 아니며, 메타데이터 정리의 로컬 fixture 검증이다.

## 유지한 진단과 근거

[진단별 근거 목록](CODE_REVIEW_M9_DIAGNOSTICS.json)에 **1,318개 전부**의
파일·행·함수·진단·유지 이유와 소스 SHA를 기록했다. 원래 Pylint 출력은
그대로 보존하며, 검토되지 않은 항목을 일괄 숨기는 설정을 추가하지 않았다.

| 주요 묶음 | 남은 수 | 유지 이유 |
|---|---:|---|
| 함수 안 import | 659 | 초기화·환경 경계, 잠재적 순환 경로, 선택 기능 및 시험의 로딩 시점 |
| 이름 재정의·미사용 인수 | 370 | fixture 식별자, 콜백/키워드 호출 계약, 기존 운영 API |
| 엄격한 타입 검사 | 135 | bool·숫자/컨테이너 하위 타입을 일괄 허용하지 않는 계약 |
| 그 외 | 154 | 실패 기록 경계, 흐름/타입 추론, 동기 콜백, 정확한 반환 형태 등 |

함수 안 import의 구분은 경로 초기화 뒤 114개, 정적 의존 그래프의 잠재적
순환 경로 96개, 수집/AI/시뮬레이션 환경 경계 20개, 플랫폼 의존 2개,
시험 실행 시 결합 171개, 선택 기능 안의 의존성 256개다. 순환 경로는 실제
발생한 ImportError가 아닌 정적 경로이며, 기능/시험 지연 로딩은 보수적인
설계 선택이다. 모든 import가 절대 이동 불가능하다고 판정한 것은 아니다.

그 외 주요 근거는 다음과 같다.

- fixture 이름 충돌 201개는 pytest의 이름 기반 주입이다. 나머지 2개는
  argparse의 `parser` 인수와 ASGI의 `app` 팩토리/진입점이다.
- 사용하지 않는 명명 인수는 시험 콜백 157개, `layout` 준비 fixture 4개,
  기존 운영 API 6개다. 운영 API는 각 인수의 실제 입력 경로와 호출 계약을
  개별 기록했다. 예컨대 `forecast_scores`의 입력은 이미 y scaler로 정규화되어 있다.
- 수집 콜백의 루프 변수 진단 14개는 같은 시도의 mutable record를 읽는
  동기 진행/자원 검사다. 다음 시도로 넘어가기 전에 소비하며 값을 고정하면
  현재 진행 상황을 잃는다. 코드에도 이 수명 관계를 명시했다.
- 넓은 예외 포착 35개는 작업 실패·원인 기록 및 정리 경계다. 각 handler의
  실제 수행 동작을 근거 목록에 포함했다.
- 빈 list/dict 직접 비교 16개는 `None` 등 다른 falsey 결과를 거부하는 시험이다.
  정확한 타입 검사와 NaN 거부 비교도 허용 입력 범위를 유지했다.
- 재노출 API, 외부 fixture 등록, 회차별 API 선택, 부모와 다른 저장 형식의
  생성자, 봉인된 생산자의 선택 AST를 검증하는 시험은 각 이유로 유지했다.
- 남은 오류 수준 진단 57개는 현재 47개·보존 10개다. 기존 타입/제어 흐름
  검토와 연결했으며 새 오류는 없다. 정적 진단 수를 실제 실행 실패 수로
  해석하지 않는다. 전체 Google 규칙 무경고 상태도 아니다.

| 검사 | 결과 |

| Data 전체 | 327 통과, 105.55초 |
| UI 백엔드 전체 최초 | 90 통과·2 실패, 79.55초 |

| 최종 시험 내부 이름/fixture 정리 | 해당 AI 파일 62개·74개 통과; 전체 수에 더하지 않음 |
| Ruff | 현재 Python 333개 포맷 일치·check 통과 |

UI 최초 실패 2개는 새 저널 검증이 헤더에도 `type` 키가 있다고 가정한
시험 코드 문제였다. 실제 UDP·시리얼 설정 요청 전송은 완료됐다. 헤더와
이벤트를 구분하도록 수정한 뒤 해당 파일의 3개가 통과했다. 최초 실패를
지우지 않았고, 한 번의 전체 92개 통과라고 표현하지 않는다.

추가한 배포 시험은 dist-info/egg-info의 이전 메타데이터만 제거하는지,
다른 패키지·코드·overlay를 보존하는지, 링크를 거부하는지를 확인했다.
UI 시험은 전송한 요청과 실제 저널의 명령·대상 기체가 일치하는지 확인한다.
전체 검사는 마일스톤 경계에 한 번씩 실행했고, 이후 새 변경/실패 관련
파일만 재검사했다. 마지막 긴 시험 이름 하나는 이름만 바뀌었음을 AST로
확인했고 이미 실행한 시험 본문은 다시 반복하지 않았다.

파일별 결과와 해시는 [M9 파일 목록](CODE_REVIEW_M9_INVENTORY.json), 로컬
원문·시험 로그·JUnit·AST 근거는 `ai/reports/code-review-20261115/m9/`에 있다.
최종 Pylint 원문은 `ai/reports/code-review-20261115/style/m9-pylint.json`이다.
이전 단계의 정적 출력과 실패 로그도 함께 유지한다.

## 남은 범위

보존 소스의 진단 2,484개와 기존 봉인 시뮬레이션 Python 시험 22개 실패는
유지한다. 실제 FC/무선·정상/이상 성능은 검증 대기다. Windows 패키지,
전송 지연 자동 추정 등 미구현 기능은 [실기체 체크리스트](../ai/LOCAL_REAL_FLIGHT_CHECKLIST.md)에서
별도로 관리한다. 이번 마일스톤은 그 기능을 구현 완료로 바꾸지 않는다.

소스 커밋은 `7f75d40`(스타일·이름·흐름)과 `bc2c2c9`(배포·UI 공개 API)로
구분했고, 근거 문서 `c94cbc7`과 함께 기존 공개 `main`에 올렸다.
[공개 CI 43628780738](https://github.com/suha0303/irion/actions/runs/43628780738)는
`c94cbc7`에서 `cpu-data`·`frontend` 모두 통과했다. CPU 253 통과·86
`local_evidence` 제외, 프런트엔드 26 통과, 빌드·포맷·Python Ruff 검사가
성공했다. 제외한 86개를 공개 환경 통과로 세지 않는다.

원본 소스 551개와 업로드본의 바이트 일치를 확인했다. 이 CI 결과만 덧붙인
후속 문서 커밋은 workflow의 경로 필터에 따라 재실행하지 않는다.
기존 PyTorch/Starlette 및 GitHub Action 런타임의 사용 중단 예정 안내는
동작 실패와 구분해 유지한다.
