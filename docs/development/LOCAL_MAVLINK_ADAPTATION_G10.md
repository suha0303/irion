# G10 MAVLink 수신 조건의 부분 파인튜닝

2026-11-15, 사용자 승인에 따라 노트북 GPU에서 최상위 예측/종료 후 모델 두 종을
부분 학습하고 새 비행으로 검증한다. 실제 PX4 X500 SITL의 UDP 수신 자료이며
실물 기체 데이터나 실제 기체 탐지 성능을 뜻하지 않는다.

## 고정한 계획

- 기존 모델·scaler·임계값·원시 자료·성공/실패·운영 선택 4,799개 파일을 봉인했다.
- 첫 정상 16회: 학습 3, 모델 선택 및 정상 잔차 기준 5, 별도 보정 8회.
- 기동 random/mixed, 바람 calm/low, 임무 480초, 초기 SOC 0.9·25℃·탑재 0.
  G9와 같은 수신 조건을 고정한다. 넓은 기체/배터리 조건으로의 일반화 시험은 아니다.
- `forecast_transformer_h64_l4`, `run_health_transformer_h64_l2` 원본에서 시작한다.
  출력층 2 epoch 뒤 마지막 내부 층과 출력층을 학습한다. 나머지 층과 scaler는 고정한다.
- 최대 100 epoch, SGD 0.001, 내부 층 개방 후 0.0001, patience 10, 원본 가중치
  이동 억제 가중치 1.0. 정상 개발 loss로만 epoch를 선택한다. 고장 자료로 선택하지 않는다.
- 두 모델 GPU 학습은 순차 실행하며 각 최대 1,260초, 합계 2,520초를 배정한다.
  데이터 수집·원시 파싱 시간은 학습 시간과 분리한다. 실제 총 시간을 따로 기록한다.
- 보정은 기존 `fit_protocol` 규칙을 그대로 사용한다. 임계값·잔차 척도는 정상 자료로만
  만들며 고장 탐지를 보고 백분위나 상수를 조정하지 않는다. 8회 보정으로 오경보율을 보장하지 않는다.
- 후보·보정값을 먼저 봉인하고 새 정상 8·이상 8회, seed 251115600~251115607을 수집한다.
  배터리/추진계 step/ramp 4종을 포함한다. 정상/이상 짝은 같은 운항 조건과 seed다.
- 수집 16병렬, 전처리/분석 최대 4병렬, GPU는 한 작업만 실행한다.
- 평가 기준: 정상 오경보, 이상 비행의 고장 전 경보, 고장 후 새 사건, 지연, 정상 예측 오차.
  종료 후 전압 건강 모델의 추진계 고장 검출은 해당 없음으로 분리한다.

비교는 원본/후보 각각에 대해 과거 원본 판정값 고정과 같은 수신 조건의 정상 보정을
나누어 기록한다. 후보에 과거 원본 판정값을 적용하는 결과는 진단용이며 자동 배포하지 않는다.
forecast의 기존 보정 규칙은 정상 잔차의 q95 척도와 고정 후보
[0.95, 0.975, 0.99, 0.995, 0.999, 0.9995, 0.9999]를 사용한다. 정상 보정 자료에서
시간당 새 경보 1개 이하가 되는 첫 후보를 고르고, 없으면 가장 낮은 경보율의 후보를
기록한다. 종료 후 모델은 8회에서 유한 표본 95% 순위를 만들 수 없으므로 기존의
임시 경험적 최댓값을 사용한다. 정상 자료만 쓰는 이 기존 자동 절차를 유지하며,
평가 결과를 보고 별도 후보/상수/백분위를 추가하지 않는다.
`calibration-rule.json`에 학습 전 명시했다. 기존 평가 함수의 보정 재계산 검산은
봉인한 값과 정확히 같은지 확인한다.
새 평가를 보고 기준을 바꾼다면 이 자료는 개발 자료가 되며 새 최종 평가가 필요하다.

## 진행 상태

첫 정상 16회는 비행과 수신 프로세스가 모두 종료 코드 0으로 끝났지만, 그중 2회는
필수 IMU가 전혀 수신되지 않았다. flight-02는 ATTITUDE 설정, flight-15는
EXTENDED_SYS_STATE 설정의 ACK가 수신 원문에 없었다. 설정 절차가 중단되어
이후 IMU 설정을 보내지 못했고, 전처리가 11초 연속 입력 부재로 거부했다.
ACK가 송신되지 않았는지 전달 중 소실되었는지는 현재 기록만으로 확정할 수 없다.
flight-02의 ATTITUDE는 이미 100 Hz로 바뀌어 설정 명령 자체는 적용된 근거가 있다.

두 시도의 원시 자료·오류를 보존하고, 모델 결과를 보기 전에 같은 seed·역할·설정으로
해당 2회만 한 차례 재수집했다. 두 재시도는 비행/수신 종료 코드 0, 필수 설정 완료로
끝났다. 성공한 14회는 그대로 사용한다. 설정 실패를 무시하거나
누락 IMU를 추정하지 않는다. 재시도는 `normal16-retry01`, 최초 실패는 `normal16`에
남으며 최종 입력 목록에 둘을 명시한다. HEARTBEAT 주기 설정 거부와 실제 수신 여부는
별도로 집계한다. PX4의 설정 거부를 모든 메시지 수신 실패로 표현하지 않는다.

최종 정상 16회는 서로 다른 원문 해시와 사전 지정 역할 3/5/8을 유지한다.
모든 비행이 한 개의 연속 사용 구간을 갖고, 전체 기록 대비 사용률은 91.0~96.0%다.
내부 정상 건강/운용 범위 검사와 joint-check는 모두 통과했다. 이 근거는 SITL의
정상 지정 근거이며 실기체 로그를 정상으로 가정하는 규칙이 아니다.
`normal16/selected-acquisition-audit.json`은 재시도를 반영한 최종 16회,
`normal16/acquisition-audit.json`은 실패 2회를 포함한 최초 시도를 기록한다.

### 부분 학습 완료

RTX 4060 Laptop에서 두 모델을 순차 학습하고 Torch 2.1.2 CPU의 별도 프로세스로
복원했다. 두 복원 검사 모두 통과했으며, 허용하지 않은 층과 scaler의 동일성을
검사했다. 학습 및 두 CPU 복원 합계는 111.10초다. 수집/파싱/보정 시간은 별도다.

| 모델 | 완료 / 선택 epoch | 종료 이유 | 학습 경과 |
|---|---:|---|---:|
| forecast Transformer h64/l4 | 100 / 100 | 사전 최대 epoch 도달 | 108.04초 |
| run_health Transformer h64/l2 | 11 / 1 | 10 epoch 개발 손실 개선 없음 | 0.64초 |

예측 모델의 개발 손실은 첫 epoch 0.14904에서 선택 epoch 0.09805로 감소했다.
이는 원본 대비 독립 정확도 개선률이 아니다. 건강 모델은 마지막 내부 층을 연 학습도
실행했으나 개발 손실이 개선되지 않아 출력층만 학습한 첫 epoch가 선택됐다.
30~60분을 모두 소모하지 않았으며, 이 작은 학습의 실행 시간을 더 많은 자료/전체
재학습이나 RTX 3050의 실측 시간으로 확대하지 않는다. 원본과의 독립 성능 비교는
아래 최종 결과에 기록했다.

정상 전용 보정 후 후보·입력·평가 코드 등 148개 파일을 `candidate-seal.json`에
봉인하고 새 평가 16회를 시작했다. 예측 원본/후보 모두 기존 정상 보정 규칙이
q=0.999를 선택했다. 건강 모델은 사전 규칙대로 8회 경험적 최댓값을 사용한다.
보정값 자체를 오경보율 보장으로 해석하지 않는다.

평가 첫 수집에서도 flight-02/06/11은 초기 ACK 누락 후 IMU가 없었다.
모델 평가 전에 첫 30초 수신 원문으로 이 3회를 확인했다.
기존 입력·보정·학습은 그대로 두고 동일 사례만 한 차례 재수집 완료했다.
16개 동시 시작에서 반복되는 ACK 누락은 미해결 통신 신뢰성 항목이다.

### 정상 개발 자료에서 확인한 착륙 전환 입력

건강 모델의 정상 개발 flight-06 오차는 약 0.11974 V/cell이며 다른 학습/개발
비행은 약 0.0036~0.0078 V/cell다. 수신 기록의 538.0초 마지막 유효 프레임에서
실제 셀 전압 3.61353 V에 대해 원본 모델이 12.18549 V를 예측했다.
이 프레임을 삭제하거나 예측값/임계값을 잘라서 성능을 다시 계산하지 않았다.

- MAVLink ATTITUDE_TARGET의 boot 540.028초에서 목표 각속도
  `[-3.8397243, -2.7962215, 3.4906585] rad/s`가 한 메시지 동안 나타난다.
- 같은 native `vehicle_rates_setpoint`의 540.028초 값도 동일하다.
  이 사례의 순간 변화는 수신 변환이 만들어낸 값이 아니다.
- 수신 시간 537.995791초에 해당 메시지가 도착했고, 다음 EXTENDED_SYS_STATE의
  LANDING=4는 538.081760초에 도착했다. 그 전에는 IN_AIR=2가 최신 상태였다.
- 해당 native 정상 검증 구간은 boot 540.020초에 끝난다. 전환 입력은 그보다
  8 ms 뒤에 있다. 임무 범위 검증과 실제 도착 시각으로 판단하는 앱 범위가 달라지는
  구체적 사례다. 이 한 사례로 모든 오경보의 원인이 설명됐다고 확대하지 않는다.

증거: `health-development-diagnostic.json`, `health-development-flight06-trace.*`,
`health-development-flight06-end-raw.json`, `health-development-flight06-end-native.json`.
이 진단은 정상 개발 자료만 사용하며 후보·보정·점수 계산을 바꾸지 않았다.
전환 입력을 포함한 학습 대표성과 수신 상태 지연 처리는 후속 검증 대상으로 남긴다.

평가 준비 자료에는 연속 구간이 여러 개인 비행도 있어, 평가 전 집계 진입점만
`run_evaluation.py`로 분리했다. 봉인한 `evaluate.one`의 추론·판정·사건·실시간
일치 검사는 그대로 호출한다. 건강 오차의 최종 표는 비행 내 유효 점수 표본 수로
가중한 RMS를 구한 뒤 비행끼리 동일 가중 평균한다. 서로 다른 길이의 구간별
오차 배열을 직접 평균하지 않는다. `evaluation-summary-addendum.json`에
모델 결과를 보기 전 기록했고 원래 봉인 파일은 유지했다. `-v2.json`에는
입력/후보/코드/출력 해시 검산 후 이미 분석한 비행을 재사용하는 절차도 기록했다.

- [x] 계획·seed·역할·학습 설정·기존 증거 봉인.
- [x] 새 정상 16회 수집·건강 근거·전처리·실수신률 검사. 불완전 수신 2회 별도 보존.
- [x] 부분 학습과 별도 CPU 복원, 정상 전용 보정·후보 148개 파일 봉인.
- [x] 봉인 후 새 정상/이상 16회 수집·독립 비교·실시간 도착/저장 경보 일치.
- [x] 기존 적용 차단 검사와 대조·AI 122개 시험·기존 4,799개 보존 재확인.

## 독립 평가 결과

정상 8회·이상 8회 최종 집계다. 수신 실패로 미리 지정한 3회의 같은 조건 재시도도
완료했으며, 처음과 재시도의 모든 원문을 보존했다. 학습·개발·보정 입력과 평가 입력의
원문 해시는 겹치지 않는다. 재시도는 모델 결과를 보기 전에 결정했다.
정상은 고장을 주입하지 않은 SITL 시나리오이며 실기체의 정상 상태 확정이 아니다.
최종 평가 16회의 설정은 모두 완료했고, 정상 비행의 내부 건강/운용 검사를 확인했다.
이상 8회는 정답 기록에서 목표 고장 크기 도달을 확인했다. 준비 구간 사용률은
90.97~95.41%, 비행당 연속 구간은 1~3개다. ATTITUDE 실수신률 99.64~99.97 Hz,
HEARTBEAT 외 필수 메시지의 ACK·조회·수신률 관측은 1,698/1,698회 통과했다.
HEARTBEAT 주기 설정 거부와 선택 신호 ESC_STATUS 미수신은 이전처럼 따로 남긴다.

| 모델 / 가중치 / 판정 기준 | 정상 오경보 | 고장 후 검출 | 예측의 고장 전 경보 |
|---|---:|---:|---:|
| 예측 원본 / 과거 고정 기준 | 8/8 | 8/8 | 8/8 |
| 예측 후보 / 과거 고정 기준, 진단용 | 8/8 | 7/8 | 8/8 |
| 예측 원본 / 같은 수신 조건 정상 보정 | 2/8 | 0/8 | 3/8 |
| 예측 후보 / 같은 수신 조건 정상 보정 | 2/8 | 0/8 | 3/8 |
| 종료 후 원본 / 과거 고정 기준 | 8/8 | 배터리 4/4 | 해당 없음 |
| 종료 후 후보 / 과거 고정 기준, 진단용 | 8/8 | 배터리 4/4 | 해당 없음 |
| 종료 후 원본 / 같은 수신 조건 정상 보정 | 3/8 | 배터리 4/4 | 해당 없음 |
| 종료 후 후보 / 같은 수신 조건 정상 보정 | 3/8 | 배터리 4/4 | 해당 없음 |

종료 후 모델은 전압 건강 판단이므로 추진계 고장 4회는 검출 분모에 넣지 않는다.
예측의 검출은 고장 후 발생한 새 전체 경보 사건이며, 고장 이전 경보를 검출로 세지 않는다.
과거 기준의 8/8 검출은 정상도 8/8 경보인 상태이므로 탐지 성능 복구로 볼 수 없다.
기준을 그대로 둔 후보가 7/8로 퇴행한 진단 결과도 숨기지 않는다.

정상 비행별 RMSE를 동일 가중 평균한 예측 오차는 다음과 같다. 구간/관측 수가
많은 비행에 더 큰 가중치를 주지 않는다.

| 예측 대상 | 원본 | 후보 | 평균 감소 |
|---|---:|---:|---:|
| p 각속도, rad/s | 0.00905035 | 0.00777231 | 14.12% |
| q 각속도, rad/s | 0.01330985 | 0.01063479 | 20.10% |
| r 각속도, rad/s | 0.01187649 | 0.01024900 | 13.70% |
| 팩 전압, V | 0.03108910 | 0.02988014 | 3.89% |

평균은 좋아졌지만 일부 비행의 q/전압 오차는 악화됐다. 같은 정상 보정 규칙에서
정상 경보 비행은 둘 다 2회, 새 경보 사건도 2개였고, 경보 판정 블록은 27→28개다.
종료 후 모델의 표본 가중 비행 RMS 평균은 0.00827006→0.00825372 V/cell로
약 0.20% 감소했지만 일부 구간 오차는 소폭 증가했고 판정 성능은 같았다.

기존 적용 검사는 예측 후보를 `known_anomaly_still_missed`,
`normal_false_alarm_regression`, `normal_prediction_regression`으로,
건강 후보를 `normal_prediction_regression`으로 거절했다.
평가 뒤 허용 오차나 기준을 바꾸지 않았다. 두 후보 모두 운영에 적용하지 않는다.
**이번 정상 3회 부분 학습으로 MAVLink 이상 탐지 문제가 해결되지는 않았다.**

## 검산과 남은 일

- 예측 16회 × 원본/후보 × 과거/정상 보정의 64개 경로, 합계 32,424개 판정 블록에서
  저장 분석과 실제 `arrived_decision`/`LiveDetector` 경로의 점수·경보가 정확히 같다.
  전체 앱의 장시간 실시간 연결 부하 시험을 대체하지 않는다.
- 기존 적용 검사가 정상 보정값을 다시 만든 값은 수집 전 봉인한 값과 정확히 같다.
  평가 자료가 보정에 들어가거나 결과에 맞춘 기준 변경은 없었다.
- 관련 AI 시험 122개가 11.57초에 통과했다. 변경하지 않은 UI/시뮬레이션 시험과
  배포 빌드를 반복하지 않았다. 실행 제품 코드는 이번 실험에서 바꾸지 않았다.
- 기존 4,799개 파일 해시 전부 동일. 원본/후보/실패 시도와 과거 검증 증거를 보존한다.
- 두 번의 16병렬 최초 수집에서 5회가 설정 ACK 누락 후 IMU 미수신이었다.
  동일 사례 한 차례 재시도 5회는 성공했다. 물리 비행 총 37회, 사용한 기록 32회다.
  자동 복구가 해결된 것으로 표시하지 않는다.

다음 마일스톤은 다음 순서다. 이번 독립 16회를 다시 학습 선택에 쓴다면 개발 자료로
전환했다고 명시하고, 성능 확인은 또 다른 seed의 새 비행에서 수행해야 한다.

1. ACK 누락 위치를 송신/수신/FC 처리 기록으로 좁히고 연결 초기 설정의 유한 복구를
   별도로 검증한다. 늦은 ACK를 다음 명령의 성공으로 오인하는 처리는 금지한다.
2. 정상 학습 자료에 수신 시점 변화·필터 재시작·착륙 전환을 충분히 포함한다.
   한 비행을 여러 시점으로 가공해도 독립 비행 수를 늘려 세지 않는다.
3. 같은 입력 조건의 부분 학습 확대와 필요 시 전체 학습을 원본 기준선과 비교한다.
   원본 scaler/모델은 별도로 보존하고, 정상 예측 오차뿐 아니라 이상 감도도 평가한다.
4. 비행 상태가 늦게 도착하는 구간은 모델 적용 가능 범위/불확실성으로 명시한다.
   고장 정답을 보고 구간을 삭제하거나 전압 예측을 임의 범위에 잘라 정상으로 만들지 않는다.
5. 후보·보정값을 먼저 고정하고 새 정상/이상 비행을 다시 16병렬 검증한다.

실기체 PX4/ArduPilot의 수신·기체별 탐지 성능, 직렬 20 Hz 조건, RTX 3050 실측,
고주기 장시간 기록/API 응답성은 별도 검증 대기다. 지금 결과는 X500 SITL UDP100이다.
