로그도 지우지 않았다.

## 실제 앱에서 발견하고 수정한 문제

- 시작 스크립트가 고정 8765 포트만 사용했다. `ARION_PORT`를 따르게 고쳤고
  8879 포트에서 실제 기동했다. 기존 8765 앱의 인스턴스가 그대로임을 확인했다.
- 브라우저가 기억한 비행 ID가 현재 데이터 폴더에 없으면 목록을 받기 전에
  시계열을 요청해 404 오류가 나타났다. 현재 목록에서 확인된 비행만
  요청하도록 고쳤다. 같은 브라우저의 저장된 선택을 남겨 둔 채 새 빌드로
  다시 열어 오류 없는 빈 화면을 확인했다.
- UI에서 예측 8종과 종료 후 8종 전환, CPU 점검 시작부터 완료까지 확인했다.
  실제 HTTP로 미확인 프로파일 저장, 셀 수 수정 시 새 버전 생성, 음수 용량
  422 거절을 확인했다. 미확인 기체를 검증 완료로 바꾸지 않았다.

CPU 점검은 PyTorch 2.1.2+cpu, 스레드 2개, 각 모델 5회 반복이었다.
16개 모두 유한한 출력이며 반복 출력 차이는 0, CUDA 초기화는 false다.
이번 합성 입력의 p95는 forecast 1.07–2.73 ms, run_health 15.85–89.10 ms였다.
입력은 각각 100/4,800프레임이다. 실제 비행 정확도나 통신 지연 보장은 아니다.
검수 서버는 종료했고 원래 실행 중이던 앱의 응답과 인스턴스는 유지됐다.

## 완료와 남은 작업의 구분

프로파일 입력, 로그 분석, 출력층 CPU 적응, 실시간 수신/분석과 종료 후
전체 런·구간별 결과는 소프트웨어 기능 검사 범위에서 통과했다. 실기체의
정상·이상 판단 및 1–3회 적응의 유의미한 성능은 독립 비행으로 검증해야 한다.
기존 실제 BIN 3개를 정상이라고 가정해 학습하거나 보정하지 않았다.
앞선 3개 로그 분석에서 확인한 원본 모델의 큰 전압 오차도 미해결이다.
forecast 8종 모두 전압 RMSE가 직전값 유지보다 컸으므로 CPU 실행 성공을
예측 성능 통과로 해석하지 않는다. 간헐적 BIN 파서 예외의 정확한 원인도
미확정이며, Python 인덱서 고정 후 미재현 상태를 유지한다.

**프로젝트 전체가 모두 정상이라는 결론은 아니다.** 시뮬레이션의 기존
22개 실패는 Recorder fixture의 인수 불일치 13개, 기존 duration 기대 2개,
native receipt의 필수 필드/검사 순서 기대 불일치 7개다. 해당 보존 소스와
과거 증거를 변경·skip하거나 봉인을 다시 써서 통과로 만들지 않았다.
개별 실패 ID와 최초/최종 로그는 로컬 `m13/simulation-baseline-comparison.json`,
`simulation.log`, `simulation.xml`에 있다.

실제 FC·시리얼/무선·비행 데이터 의미·독립 정상/이상 성능은 **검증 대기**다.
전송 지연 자동 추정, 4로터 외 모델, ULog 복수 부팅 자동 복구, 전체 사용자
데이터 경로 자동 이관, Windows 패키지는 **미구현**이다. 자세한 상태는
[실기체 체크리스트](../ai/LOCAL_REAL_FLIGHT_CHECKLIST.md)를 따른다.
이번 최신 소스 검수로 기존 RC12 배포 압축 파일이 갱신되지는 않는다.

## 이 개발 PC에서 최신 소스 실행

현재 설치된 환경·모델·빌드된 UI를 사용한다. 이 명령은 기존 앱과 별도로
8879 포트를 쓰며, 데이터는 지정한 폴더에 보존된다.

```bash
cd /home/sa/CapstoneV3
ARION_AI_ROOT="$PWD" \
ARION_DATA_DIR="$PWD/ai/.local/current-ui" \
ARION_PORT=8879 \
./irion-upload/UI/start.sh
```

브라우저에서 `http://127.0.0.1:8879`를 연다. 실행 터미널에서 `Ctrl+C`로
종료한다. 서버를 재시작할 때 같은 데이터 경로를 사용한다. 새 폴더에는
기존 앱의 기록이 자동 복사되지 않는다.

모델 목록만 확인하려면 다음을 실행한다.

```bash
cd /home/sa/CapstoneV3
./ai/drone-ai local catalog
```

‘로컬 AI · 기체 관리’에서 모델·프로파일·로그·적응을 사용한다.
‘실시간 연결 → 기체별 로컬 AI’는 한 기체를 연결하며,
‘비행 종료 · 결과 분석’ 뒤 전체 런 요약과 구간별 상세/제외 구간을 본다.
설치형 RC12 사용법은 [Ubuntu 안내](../ai/LOCAL_DESKTOP_UBUNTU.md),
재현 가능한 회귀 명령은 [TESTING.md](TESTING.md)에 있다.
