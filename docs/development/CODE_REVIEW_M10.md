M9에서 fixture 이름 충돌을 보수적으로 남겼지만, pytest의 공개 API인
`@pytest.fixture(name="...")`를 사용하면 주입 이름과 구현 함수 이름을
분리할 수 있다. 두 시험 파일에서 가져오는 공유 fixture도 새 구현 이름으로
등록하되 기존 주입 이름을 유지했다.
[pytest 공식 문서](https://docs.pytest.org/en/stable/reference/reference.html#pytest-fixture)

콜백은 인수 이름을 바꾸지 않고 `del`과 이유 주석으로 미사용을 나타냈다.
본문이나 중첩 함수가 실제로 읽는 인수는 제외했다. `yield`를 포함한
contextmanager의 미사용 인수 1개는 생성기 프레임의 인수 수명을 보존했다.
[Google의 미사용 인수 지침](https://google.github.io/styleguide/pyguide.html#21-lint)

**385개도 경고 자체를 영구히 남겨야 한다는 뜻은 아니다.** 보존해야 할 것은
동작과 호출 계약이다. 412개는 필수 유지로 판정하지 않았으며 아직 완료하지
않은 코드 검토 대상이다. 모두 실기체 데이터 없이 검토할 수 있다.

추가 검토 412개는 선택 기능 import 244개, 잠재적 순환 경로 import 96개,
시험 import 28개, 정적 타입/제어 흐름 42개, fixture 반환 추론 1개,
항상 차단하는 seal 분기 1개다. 전체 정적 import 그래프의 순환 경로만으로
실제 최상위 import 실패가 발생한다고 단정하지 않는다. 선택 기능 import는
CPU 수집 환경·CLI의 불필요한 Torch 로딩 여부부터 확인해야 한다.

각 진단의 파일·행·함수·유지/추가 검토 분류·근거·다음 작업을
[진단 목록](CODE_REVIEW_M10_DIAGNOSTICS.json)에 기록했다. M9의 보수적인
유지 분류를 그대로 최종 면제로 취급하지 않는다.
