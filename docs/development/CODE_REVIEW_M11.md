# M11 — 남은 412개 검토 완료

2026-11-15. 기준 커밋 `6999afa`. M10에서 남긴 후보 **412개 중 220개를
정리하고 192개는 현재 실행 계약에 필요한 이유를 기록해 유지**했다.
현재 코드의 Pylint 진단은 **797 → 578개**다. 기존 후보 220개를 없애고,
worker 환경 준비 뒤 모듈을 불러오는 묶음 import 진단 1개가 추가됐다.
기존 유지 385개 + 이번 유지 192개 + 초기화 순서 1개 = 578개다.

보존 소스의 진단 2,484개는 그대로이며 전체는 3,062개다. 오류 수준 진단은
현재 43 → 36개, 보존 소스 포함 53 → 46개다. Google pylintrc·전역 예외
설정을 바꾸거나 dummy 값·cast를 넣어 진단을 감추지 않았다.

운영 import 192개와 시험 import 20개를 모듈 수준으로 정리했다. 호출은

지역 대입을 유지해 monkeypatch와 분기별 바인딩을 보존했다. 서로 참조하던
두 시험 정책 생성기는 기존 공통 시험 모듈에 모았다. 정책 내용은 동일하다.

빈 큐·유효 구간이 없는 경우를 먼저 처리하여 실제 값이 있는 분기에서만
행과 마지막 구간을 바인딩한다. 큐의 None 종료 표식은 유지한다. 항상
예외를 내는 `seal`은 `NoReturn`과 즉시 반환 호출로 의도를 명시했다.
진단 정책 검증 함수는 모듈 외부 호출에 맞는 공개 이름으로 정리했다.

## 발견한 문제와 검증

import를 옮기는 중 새 프로세스 점검에서 패키지 `__init__`을 경유하는
순환 참조로 5개 진입점이 실패했다. 해당 import를 기능 경계로 되돌렸고,
CLI에서 NumPy를 추가 로드하던 4개 import도 되돌렸다. 이후 **65개 모듈의
새 프로세스 import가 통과**했다. 비교 가능한 기존 62개 모듈에서는 무거운
의존성이 추가되지 않았다. 실제 순환을 재현한 진입점 5개는 회귀 시험에
추가했다. 정적 import 그래프만으로 안전하다고 판단하지 않았다.

전체 AI 검사에서는 독립 배포 패키지가 `x500_storage`/`pretrain.storage`를
요구하는 회귀가 8개 시험에서 발견됐다. 준비 기능의 import 6개를 원래
호출 경계로 되돌려 해결하고, 관련 준비·저장소 시험 60개를 재검사했다.
최초 실패 로그와 후속 통과 로그를 모두 보존했다.
