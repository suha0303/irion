## M7 — 긴 행과 설명

255개 파일의 긴 문자열·주석·docstring을 정리했다. 문자열은 인접 리터럴로
나누어 원래 값을 유지하고, 줄 끝의 긴 설명은 해당 코드 앞에 배치했다.
실행 AST는 docstring을 제외하면 기준 커밋과 전부 같다. 모델·임계값·계약·
기존 출력 문자열을 바꾸지 않았으며 보존 파일 178개의 해시도 같다.
현재 소스의 긴 행 진단은 1,290개에서 45개로 줄었다.

큰 마일스톤 경계에서 AI **1,483개**, Data **327개**, UI 백엔드 **92개**의
전체 검사를 각각 한 번 실행했고 모두 통과했다. 부분 재검사를 합산한
수치가 아니다. 커밋: `a61ab15`.

## M8 — 이름·import·콜백

137개 파일을 정리했다. 주요 변경은 다음과 같다.

- 미사용 변수 바인딩 74개를 `_`로 표시했다. 반환값이 필요 없더라도
  검증·기록·자원 생성 호출과 unpacking은 유지한다.
- 단순 래퍼 람다 24개를 실제 callable로 바꾸고, 표준 라이브러리 import
  90개를 상단으로 옮기거나 중복 제거했다. 선택 의존성·플랫폼 분기·
  실행 환경 초기화 순서에 의존하는 import는 그대로 두었다.
- 기본 제공 이름 충돌 19곳을 정리하고 테스트·배열·콜백 인수 이름을
  구체화했다. JSON 키와 파일 형식은 그대로다. `StoreV2.get(run_id=...)`는
  부모 클래스와 인수 이름을 맞추고 기존 migration 시험에서 호출한다.
- 모듈 설명 35개, 클래스 설명 15개를 보강했다. 긴 시험 이름과 내부
  Python 프로그램 문자열도 정리했다. 내부 프로그램 3개는 각각 실행
  AST가 동일함을 확인했다.
- 문자열의 첫/마지막 조각만 필요한 11곳은 `maxsplit=1`을 쓴다.
  텍스트 성능 보고서는 작은 포맷 함수로 나눴으며 출력 동등성을 확인했다.
- 불명확한 혼합 연쇄 비교와 불필요한 취소 예외 재전파를 정리했다.
  Python 3.10/3.12의 `CancelledError`는 `BaseException` 계열이므로
  이어지는 `except Exception`에 잡히지 않고 기존 `finally`를 거친다.

현재 소스의 긴 행, 모듈·클래스 설명 누락, 미사용 변수, 래퍼 람다,
기본 제공 이름 충돌, 잘못된 이름과 불필요한 전체 문자열 split 진단은
각각 0개다. Ruff check와 80열 formatter도 수정 가능한 Python 333개에
적용한다. 보존 소스를 규칙 예외로 더 추가하지 않았다.

## 남은 진단의 처리 기준

- 늦은 import **677개**: 선택 의존성, CLI/worker 초기화, 시험 내부의
  선택 모듈 로딩을 포함한다. 전부 필수 예외라고 단정하지 않으며,
  추가 이동 시 import 비용·순환 의존·환경 초기화 순서를 확인해야 한다.
- 외부 이름 재정의 **253개**, 미사용 인수 **217개**: 대부분 pytest
  fixture 주입과 콜백/프로토콜 서명이다. 무조건 인수 이름을 바꾸면
  fixture나 키워드 호출이 깨진다.
- 정확한 타입 검사 **135개**는 JSON 정수·실수에 `bool`이 섞이는 것을
  거부하는 계약을 포함한다. NumPy 배열의 길이 검사 **10개**도
  배열의 모호한 truth value 문제 때문에 단순 `if array`로 바꾸지 않는다.
- 빈 list/dict와 직접 비교하는 시험 **16개**는 `None` 등 다른 falsey
  반환값을 통과시키지 않도록 유지한다. 사용하지 않는 import **5개**와
  import alias **2개**는 API 재노출 또는 pytest fixture 등록이다.
- 중복 import **7개** 중 5개는 기체/실행 단계별 같은 API의 분기 선택이다.
  2개는 조건부 경로의 표준 라이브러리 중복으로 추가 단순화할 수 있다.
  import 순서 **4개**는 저장 루트 환경 변수와 simulator 경로 초기화에
  의존한다. 생성자 **2개**는 부모의 다른 저장/원장 초기화를 쓰면 안 된다.
- 나머지 예외 경계, 테스트의 내부 API 접근, 즉시 소비되는 루프 클로저,
  조건부 초기화는 기존 코드 검토 근거와 함께 유지한다. Pylint 오류 수준
  진단 **59개**(현재 49, 보존 10)는 M6와 내용이 같으며 새 오류는 없다.
  이는 모두 실제 오류가 사라졌다는 주장이 아니다.
