# G8 원본 검출 성능과 로컬 평가 차이

2026-11-15. 사용자 요청: 원본의 100% 검출이 현재 시험에서 사라진 원인과
시뮬레이터 변경 영향을 추적한다. 새 비행은 16병렬, 그 외 작업은 최대 4병렬이다.
기존 원본 모델·scaler·판정값·비행·후보·평가 기록을 보존한다.

## 먼저 바로잡은 설명

이전의 ‘과거와 같은 점수·후처리’는 최종 사건 성공 조건까지 동일하다는 설명으로는
잘못됐다. 공통 점수/EWMA/지속 조건을 연결했지만, 로컬 평가에서 고장 주석의
`target=propulsion`을 추진 신호 영역의 새 경보만 인정하는 조건으로 사용했다.
과거 최종 평가는 어느 신호 영역이든 전체 경보의 새 에피소드가 시작되면 검출 성공이다.
신호 영역과 실제 고장 원인을 혼동한 구현·검증 누락이다.

과거의 ‘100%’는 독립 이상 243/243 검출률이다. 정상까지 포함한 정확도 100%가
아니다. 당시 forecast 정상 오경보는 38/486회, 종료 후 모델은 15/486회였다.
기존 성공을 취소하지 않되 당시 시험 범위와 현재 통신 경로의 성능을 혼동하지 않는다.

과거 저장 예측을 변경 없이 재계산한 결과:

| 과거 독립 사건 | 전체 새 경보 검출 | 주석된 신호 영역의 새 경보 |
|---|---:|---:|
| 배터리 급변 | 27/27 | 27/27 |
| 배터리 점진 | 27/27 | 27/27 |
| 추진 급변 | 27/27 | 1/27 |
| 추진 점진 | 27/27 | 1/27 |

추진 고장이 전압 변화를 일으킬 수 있고 제어기가 각속도를 유지할 수도 있다.
전압 경보가 난 추진 고장을 ‘미검출’로 세면 과거 검출 성능과 비교할 수 없다.
그렇다고 전압 경보만으로 추진 고장의 원인을 확정할 수 있는 것은 아니다.

수정된 `normal-and-anomaly-regression/2`는 forecast에서 과거와 동일한 **전체 경보의
새 에피소드**를 사건 검출에 사용한다. 고장 전에 이미 켜진 경보는 새 검출이 아니다.
주석된 신호 영역의 경보는 별도 진단 필드로 보존한다. 정상 오차·정상 오경보 증가,
검출 손실·지연에 대한 후보 거절 조건은 유지한다. 종료 후 voltage-health의 추진
고장 원인 판정은 여전히 지원 범위가 아니며 별도 표시한다.

기존 `/1` 결과·모델·보정값은 재작성하지 않았다. 새 적응 작업은 `/2`를 기록하며
앱은 이전 평가와 새 지표를 구분하고 ‘원본’이 원본 가중치라는 뜻임을 설명한다.
작업 결과 탭에서 파인튜닝 결과 본문이 비어 있던 문제도 공통 결과 표시로 수정했다.

## 시뮬레이터가 바뀌었는가

최종 평가 인수 캐시 891개는 모두 같은 생산자 봉인
`a3467c7277ce68e5ad73f36484f36d9f226f03c1cf72c6c7e4447360bba4d53f`를 참조했다.
이를 G8 수정 전 실행 봉인의 실제 768개 파일과 비교했다. PX4 실행 파일,
물리 플러그인, 배터리·추진 프로파일, 랜덤 경로·제어 관련 소스는 같았다.
달라진 파일은 실행기, source/runtime 봉인 관련 목록, 종료 시험뿐이었다.

실행기 변경은 SIGTERM 시 소유 자식 회수, PX4 `-d`/표준입력 닫기,
예외 발생 시 실패 상태 보존이었다. 물리 파라미터나 고장을 약하게 만든 변경은 없었다.
현재 768개 파일의 실제 해시도 봉인과 일치했다. 11월 15일 기능별 업로드 커밋 시각은
과거 구현을 Git에 올린 시각이며, 그날 처음 물리를 변경했다는 뜻이 아니다.

## 달랐던 학습·운항·입력 조건

실제 본학습/최종 수집 계획 1,674개의 조건을 확인했다. 초기 잔량 90%, 온도 25℃,
추가 탑재량 0kg는 모두 고정이었다. 기동 9종과 calm/low/strong 바람은 달랐다.

| 조건 | 과거 최종 자료 | 최근 G6/G7 시험 |
|---|---|---|
| 임무 길이 | 480초 | 180초 |
| 임무 시작 | native 공통 단계, 부팅 약 60초 | 상승 도중 약 19초 |
| 고장 시작 | 임무 180/240/300초 후 | 임무 60초 후 |
| 초기 잔량 | 90% | 72/85/90/95% |
| 온도 | 25℃ | 15/20/25/30℃ |
| 추가 탑재량 | 0kg | 0/0.02/0.04/0.08kg |
| 입력 | 내부 uORB 가용 시각, 임무 전체 | MAVLink 수신 시각, 이륙/착륙 포함 |
| 보정 | 동결된 검증/보정 자료 | 새 정상 개발/보정 비행 |

같은 X500라는 이유만으로 학습 범위와 같은 시험이라고 해석한 것은 부정확했다.
최근 시험은 범위를 넓힌 조건으로의 이전 성능 시험이다. 같은 새 native 센서 기록을
과거 수집 엔진과 현재 로컬 sampler에 넣으면 19개 입력이 정확히 같았다(정상/이상
각 1회). 단위나 필터 수식의 변경으로 설명되는 문제가 아니었다.
같은 비행의 MAVLink 입력에는 전송 주기·수신 시각의 차이가 남았다.

G7의 넓어진 정상 자료에서 초기 과도 잔차가 크게 증가해 새 보정 기준도 높아졌다.
이는 수동 임계값 조정이 아니라 정상 자료에 같은 계산을 적용한 결과다. 모델의 예측
범위가 충분한지 확인하지 않고 보정만으로 오경보를 줄이면 이상까지 묻힐 수 있다.
G7 고장 4회를 `/2`로 다시 계산해도 원본/후보 forecast 0/4, 종료 후 배터리 0/2였다.
평가 방식 수정 하나로 모든 미검출이 해결된 것은 아니다.

## 새 16병렬 대조

기존 weights/scaler/원본 판정값을 고정했다. seed 251115300–307, 정상/고장 8쌍을
16개 인스턴스로 동시에 실행했다. 과거와 같은 480초/60초 native 임무 시작, 잔량
90%/25℃/추가 탑재량 0kg, random/mixed 경로와 calm/low 바람을 사용했다.
배터리 급변/점진 및 추진 급변/점진은 임무 300초 후 주입했다. 새 보정·학습은 하지 않았다.

첫 시도 15회 완료, 1회 착륙 전환 실패. 실패한 비행과 같은 seed의 정상 짝을
수정 후 재실행해 둘 다 완료했다. 기존 정상 짝을 중복 집계하지 않은 최종 정상
8회·이상 8회의 대조다. 첫 실패 기록과 이전 15회 집계도 별도로 보존했다.

| forecast 경로·기준 | 정상 오경보 | 고장 후 전체 새 경보 검출 |
|---|---:|---:|
| 내부 입력 + 과거 원본 기준 | 0/8 | 8/8 |
| MAVLink 전체 비행 + 과거 원본 기준 | 8/8 | 7/8 |
| MAVLink 임무 구간 진단 + 과거 원본 기준 | 4/8 | 7/8 |
| 내부 입력 + G7 정상 기반 기준 | 0/8 | 0/8 |
| MAVLink 전체 비행 + G7 정상 기반 기준 | 0/8 | 1/8 |

종료 후 모델도 내부 입력/원본 기준에서는 정상 0/8 경보, 이상 8/8 경보였다.
여기서 추진 사건의 전압 경보는 ‘이상 반응’이며 고장 원인 식별 성공으로 확대하지 않는다.
MAVLink 경로의 마지막 배터리 급변 사례는 고장 전에 켜진 경보가 계속 유지돼
고장 후 새 경보 검출로 세지 않았다. 종료 후 경보 8/8도 정상 오경보 8/8과 함께 읽어야 한다.
MAVLink의 임무 구간 제한은 원인 대조용이다. 시뮬레이터 내부 시간을 실기체 입력에
몰래 사용하지 않았고, 앱을 60초간 무조건 숨기도록 변경하지 않았다.

첫 시도 실패도 평가 분모와 별도로 보고한다. 실패를 검출 성공/정상 비행으로
포함하지 않는다. 이 작은 대조를 새 일반화 정확도나 실기체 성능으로 보고하지 않는다.

## 별도로 발견한 착륙 실행 오류

첫 시도 flight-10에서 native LAND 발행 시각은 540.004초였고, 마지막 위치 메시지는
539.756초였다. HEARTBEAT는 이미 AUTO 모드인데 실행기가 오래된 위치 시각으로
임무가 아직 끝나지 않았다고 판단해 중단했다. 고장 주입 전후의 물리 문제는 아니었다.
이 경합 조건은 이전 원본 실행기에도 있던 조건이다.

실제 native LAND 발행 기록을 검증해 모드 전환 대기를 허용하도록 수정했다.
착륙 완료 native 소비 기록·기존 최종 검사는 그대로 필요하다. 조기/누락/잘못된
LAND 기록은 모드 이탈을 숨기지 않는다. 위치 시각 오차 허용치를 늘리지 않았다.
이전 생산자 봉인을 보존하고 기존 설치기의 공유 잠금/봉인 절차만 실행했다.
PX4·물리 바이너리와 고장 파라미터는 다시 바꾸지 않았다.

실패한 비행과 정상 짝만 같은 seed로 재실행했다. 동시 실행 한도는 16이며 남은
작업이 두 개라 두 슬롯만 사용했다. 통과한 다른 14회는 반복하지 않았다.
재시도는 독립 새 데이터로 부풀리지 않고 같은 pair/retry 계보로 관리한다.
두 재시도는 비행·수신 종료 코드 0, native 착륙 소비 및 joint-check 통과다.
임무 길이는 각각 480.016초/480.024초이며 실제 착륙 전환 꼬리도 보존했다.
