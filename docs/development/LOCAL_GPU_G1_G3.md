# 로컬 GPU 기체 적응 G1–G3

2026-11-15. 원격 서버 없이 현재 노트북에서 실행했다. 사용자는 별도
`ai/.local/gpu-runtime` 설치를 명시 승인했다. 시스템 CUDA 13.4, 기존 CPU
Python 3.10.22/PyTorch 2.1.2+cpu 및 원본 모델·scaler·threshold는 유지한다.
GPU 환경은 Python 3.10.22/PyTorch 2.5.1+cu121, RTX 4060 Laptop이다.
CUDA 툴킷과 PyTorch가 포함하는 CUDA 런타임의 버전은 같을 필요가 없다.

## 구현과 선택

- 최신 16종을 유지하며 한 작업은 forecast 1종 + run_health 1종을 순차 학습한다.
- 동결된 729-run X500 평가의 balanced accuracy로 forecast Transformer h64/l4
  (0.960905), run_health Transformer h64/l2 (0.984568)를 선정했다.
  과거 평가를 새 실험의 선택에 사용했으므로 그 수치를 새로운 독립 검증 결과로 주장하지 않는다.
- 첫 2 epoch는 출력층, 이후 마지막 내부 층과 출력층을 갱신한다. 내부 층 단계의
  학습률은 0.0001, 출력층은 0.001, SGD·gradient clipping·원본 가중치 변화 억제를 사용한다.
  출력층 단계는 고정 표현을 CPU에 캐시한다. 구조·입력 계약·scaler는 변경하지 않는다.
- 별도 정상 개발 비행으로 최선 epoch를 저장하며 조기 종료, 완료 epoch 재개,
  30/60분 전체 예산을 제공한다. 학습에 70%, 비교·CPU 복원·저장에 나머지를 확보한다.
  단일 연산은 선점할 수 없으므로 예산 초과 시 통과로 표시하지 않고 적용을 막는다.
- 정상 예측 오차·오경보 증가, 기존 이상 미탐·지연, 알려진 이상을 양쪽 모두 놓침은
  적용 거절이다. 이상 시점/대상 또는 평가 자료가 없으면 검증 대기다.
  배터리 시험에 Yaw 경보나 고장 전 경보를 검출 성공으로 세지 않는다.
- 후보의 가중치·scaler를 검사하고 실제 배포 CPU 인터프리터로 별도 프로세스 복원·추론한다.
  통과 후보도 자동 활성화하지 않으며 사용자가 모델과 해당 보정값을 함께 선택한다.
  알려진 몇 사례의 퇴행 검사이며 미지의 모든 비행에 대한 성능 보장은 아니다.

## 고정 자료 비교

정상 학습 1회(2,135프레임/213.5초), 정상 개발 1회(2,147프레임/5개 보존 구간),
정상 보정 2회, 정상 평가 1회, 배터리 이상 평가 1회다. 원본 해시가 모두 다르다.
개발 비행은 학습과 같은 seed 경로의 다른 기록이며 이전에 본 SITL 자료를 재사용한
회귀 검사다. 실기체 BIN 3개는 건강 상태 unknown으로 남겨 학습에 사용하지 않았다.

| forecast 팩 전압 RMSE (V) | 0.03750 | 0.02431 | 0.03036 |
| run_health 셀 전압 복합 오차 (V) | 0.06517 | 0.04130 | 0.06136 |

run_health 지표는 short/long cell-voltage 잔차의 제곱합 제곱근이며 forecast RMSE와
같은 지표가 아니다. forecast의 직전값 유지 전압 RMSE는 **0.01487 V**로 여전히 더 좋다.
출력층 forecast는 Roll RMSE가 0.0089879→0.0090414 rad/s로 증가하여 추가 거절됐다.
**이 자료에서 부분 학습이 출력층 학습보다 우수하다고 결론 내릴 수 없다.**

첫 부분 학습 작업은 내부 타이머 7.53초(두 학습·보정·비교·저장)였다.
forecast 학습 5.13초, run_health 학습 0.89초, 각 30 epoch이며 PyTorch 최대
텐서 할당량은 약 32 MiB였다. 드라이버/컨텍스트 전체 VRAM 사용량과 다르다.
출력층 학습은 각각 2.41초/0.69초였다. 최초 설치·프로세스 기동은 이 수치에서 제외한다.
기존 CPU 2.1 환경의 별도 복원·추론은 이후 네 후보 모두 통과했다.
작은 모델과 짧은 학습 비행의 결과이며 RTX 3050 측정·긴 로그 처리 시간 검증이 아니다.

## 배터리 미탐 원인 추적

forecast 원본의 정상 보정 첫 비행에서 Yaw 표준화 오차의 99분위가 13.598로
공통 경보 기준을 결정했다. 배터리 이상 구간의 전압 최대 점수는 0.8145,
부분 학습 후에는 0.8045로 각각 기준 13.598/13.424보다 훨씬 작다.
전압만의 정상 99분위도 1.0527/0.9980으로 이상 구간 최대보다 크다.
따라서 신호별 기준으로 나누기만 해도 이번 이상을 잡는다고 단정할 수 없다.
whole-flight의 단일 경보도 이 배터리 구간의 전압 검출이 아니다.

run_health 원본의 이상 점수 0.7085는 보정 기준 0.9309보다 작고, 정상 평가 점수
0.8304보다도 작다. 부분 학습 후에도 이상 0.6572 < 정상 0.7819 < 기준 0.8873이다.
현재 관측·점수에서 이 사례는 건강 상태 순서대로 분리되지 않는다.
단위나 GPU 저장 오류로 판명된 것이 아니며, 원본부터 놓쳤으므로 이 사례를
“파인튜닝 때문에 검출 상실”로 보고하지 않는다. 고장 자료에 맞춰 기준을 낮추지 않았다.
