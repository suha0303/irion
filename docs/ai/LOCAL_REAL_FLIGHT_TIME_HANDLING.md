# 실기체 로그의 시간축·기록 중단 처리

기준: 2026-11-14. 구현은 `ai/localflight/`, 화면은 `irion-upload/UI/`.
기존 시뮬레이션 데이터 계약·평가·모델·scaler·threshold는 수정하지 않는다.

## 실제 BIN 3개에서 확인한 것

| 로그 | 주요 센서의 최대 공백 | 공통 기록 구간 길이 |
|---|---:|---|
| 00000005.BIN | 약 963.7초 | 57.5 / 711.6 / 708.0초 |
| 00000011.BIN | 약 882.2초 | 57.6 / 678.2 / 675.6 / 346.7초 |
| 00000198.BIN | 약 234.8초 | 103.7 / 848.8 / 850.9초 |

이번 인스턴스별 검사에서 주요 센서의 시간 역행·중복은 0이었다.
공백의 원인은 아직 확인하지 못했다. 지상 대기·로깅 설정·기록 중단 중 하나로 단정하지 않는다.
이 구간들은 관측된 필수 후보 메시지의 기록 범위 교집합이다. 비행 중·정상 비행·19입력의
완전성·모터 채널/좌표 매핑까지 확인된 구간은 아니다. 기체 사양과 정상 여부는 미확정이다.
원본 해시·구간 시작/종료·센서별 결과는 `ai/reports/local-real-flight-20261114/timing-summary.json`
및 `*.timing-audit.json`에 있다. 과거 파서 경고가 포함된 기록도 지우지 않는다.

## 실제 분석에서 추가 확인한 내용 (2026-11-14)

후속 분석에서는 ArduCopter 4.4.0의 EV 28/18을 대조해 실제 기록된 이륙/착륙 구간
11개를 선택했다. 00000005의 XKF4.PI 전환을 추가로 분리해 12개 패키지로 실행했다.
47,737개 완전 프레임에 16종 모델을 모두 실행했으며 건강 상태는 미확정으로 유지했다.
이 구간별 선택은 분석 스크립트의 기능이며 UI 자동 분리 구현으로 표시하지 않는다.
보고서: `ai/reports/real-flight-analysis-20261114/REPORT.md`.

## 처리 순서

1. 원본을 해시로 식별하고 그대로 보관한다. 파서가 읽은 부팅 시각을 기준으로 센서별,
   인스턴스별 공백·중복·역행을 진단한다. 0.5초 공백 표시는 탐색용이며 오차 합격선이 아니다.
2. 기체 프로파일의 모터 위치/채널·출력 범위·배터리·센서 인스턴스를 명시한다.
   ArduPilot 단위는 파일의 FMTU/UNIT 메타데이터를 따른다. 예를 들어 CTUN CRt/DCRt의
   cm/s를 m/s로 변환한다. 단위가 확인되지 않은 신호를 숫자 크기로 추측하지 않는다.
3. 사용자가 검사할 시작·종료를 지정한다. 최대 2시간 범위에서 100 ms 격자를 만들고,
   그 시각까지 도착한 관측만 사용한다. 미래 표본으로 과거 입력을 보간하지 않는다.
4. 기본 관측 유지 시간은 운동/명령 200 ms, 배터리 350 ms다. UI에서 각각 20~2000 ms로
   조정할 수 있고 설정을 결과에 남긴다. 이는 CPU/GPU 수치 허용오차와 다른 결측 정책이다.
   유한한 각속도·가속도 값은 크다는 이유만으로 제거하지 않는다. 실제 정상 범위는 별도 평가한다.
5. 결측·유효성 상실·오래된 표본·기록 중단에서 구간을 나눈다. 필터 상태를 새로 시작한다.
   완전한 19입력이 110시점(11초) 이상 보존된 구간을 UI에서 선택한다. 선택 구간 합계는
   CPU 작업 1회당 1000초까지다. 제외 시점 수·신호별 누락·사용률을 결과에 남긴다.
6. forecast의 100시점 입력과 이후 10시점 정답은 반드시 같은 구간에 둔다.
   run_health도 각 구간을 별도 forward로 실행하고 결과를 분리한다. 불완전 비행을 온전한
   한 비행의 건강 판정으로 표시하지 않는다.

새 전처리 revision은 `real-common19-segmented-v2`다. NPZ에는 실제 시각과 유한한 보존
프레임만 저장하고, manifest의 `segments`로 경계를 명시한다. 배열을 연달아 저장해도
시간 공백을 없애거나 모델 문맥을 연결하지 않는다. 예측 창은 구간 시작에 맞춰 1초 간격이다.

## 시간축이 실제로 어긋났을 때

UI의 ‘관측 유지 시간과 시계 보정’에서 센서 기록 이름과 확인된 동기점 2개를 입력한다.
예: `BAT:0`, `battery_status:0`. 동기점은 원래 시각과 공통 시각의 쌍이며 단위는 초다.
CLI 내부 프로토콜은 2~100개의 μs 쌍을 지원한다.

보정식은 `공통 시각 = scale × 원래 시각 + offset`이다. 일정 시간차와 일정한 시계 드리프트를
함께 다루며, 동기점 범위 밖으로 외삽하지 않는다. 양의 기울기·증가하는 동기점·근거가 필요하다.
계수·ppm·최대 동기점 잔차·근거·원본을 보존한다. 여러 동기점에 맞지 않는 비선형 왜곡은
별도 연속 구간으로 나눠 확인한다. 자동으로 곡선을 휘거나 모델 오차를 최소화하도록 맞추지 않는다.

명령과 실제 기체 반응 사이의 지연은 물리 현상일 수 있다. 상관관계만으로 그 지연을
시계 오류라고 보고 제거하지 않는다. 동기화 근거 없이 기존 3개 BIN에 시계 보정을 적용하지 않았다.
보정된 데이터는 `offline_clock_reconstruction`으로 표시한다. 사후 동기점을 쓴 결과를
실시간 처리 성능으로 주장하지 않는다. 공간 좌표/축 회전 보정은 기체 매핑 근거 확인이 별도로 필요하다.

## 리셋·손상 범위

- BIN: 파일 순서에서 첫 선택 센서 시각 역행 또는 파싱 경고를 만나면 그 앞부분만 보존한다.
  오류 위치와 이유를 기록하며, 다음 부팅을 앞의 시각에 정렬해 섞지 않는다.
- ULog: dropout 메타데이터의 앞뒤를 경계로 삼고 그 사이 관측을 제외한다.
  토픽 배열만으로 부팅 간 대응을 확정할 수 없는 시각 리셋은 자동 합치지 않는다.
  이런 파일은 부팅별로 분리된 원본/추출 로그가 추가로 필요하다.
- 파서 초기화 단계의 경고처럼 안전한 바이트 경계를 모르는 손상은 자동 복구 대상으로 삼지 않는다.
- 양쪽 입력 모두 중복 시각은 먼저 기록된 표본을 유지한다. 원본은 삭제하거나 덮어쓰지 않는다.

BIN 리셋·파서 손상 앞부분 회수는 합성 파서 시험을 통과했다. 실제 고장 로그 복구와 실제 PX4
검증은 아직 수행하지 않았다. PX4 파서 확인에는 기존 시뮬레이션 ULog를 fixture로만 사용했다.

## 학습·평가와 UI 사용

`irion-upload/UI/server.sh start` 후 로컬 대시보드의 ‘로컬 AI · 기체 관리’를 연다.
기존 `ai/.venv`와 `irion-upload/UI/.venv`, 빌드된 frontend가 필요하다. 개발 소스에서 실행하는 명령이다. Python과 모델을 포함한 Ubuntu RC3 배포 후보의
실행·복원 방법은 `docs/ai/LOCAL_DESKTOP_UBUNTU.md`를 따른다.

‘로그 검사 → 프로파일 등록 → 보존 구간 검사 → 구간 선택/저장 → 모델 A/B 분석’ 순서다.
검사 완료 작업의 프로파일/시간 설정에 선택 결과를 묶고, 검사 뒤 원본이 달라지면 저장하지 않는다.
정상 여부가 모르는 로그는 예측용으로 준비할 수 있지만 정상 적응 학습에는 넣지 않는다.

적응은 forecast 모델 A의 출력층만 CPU에서 수행한다. 정상 확인 비행 1~3개, 최대 20 epoch,
고정 scaler, 새 가중치 파일, 별도 체크포인트를 사용한다. 중지 후 마지막 완료 epoch에서 재개할 수 있다.
동일 로그를 여러 구간으로 나눠도 원본 해시가 같으므로 다른 역할이나 독립 비행으로 중복 사용하지 못한다.
독립 평가에서는 원본·적응 모델·직전값 유지 기준의 오차를 비교한다. 기존 threshold를 자동 승계하지 않는다.

다음 확인 사항은 기체/배터리 사양·모터 매핑·센서 인스턴스·이착륙 구간·비행 건강 상태이며,
Ubuntu 배포 후보·예측 시계열 그래프·모델 채택/원복은 구현했으며, 별도 PC 배포 확인과
실기체 탐지 성능 검증은 전체 체크리스트에서 계속 추적한다.


## RC11 이벤트 기반 선택

ArduCopter 4.4.0 BIN 검사 결과는 EV.NOT_LANDED(28)→EV.LAND_COMPLETE(18)의 닫힌 비행 구간을 제공한다.
XKF4.PI 전환에서 나누며 고정 EK3_IMU_MASK·AHRS_EKF_TYPE=3·관측된 IMU를 근거로 구간별 센서를 선택한다.
사용자가 선택한 자동 구간 번호는 서버가 검사 결과의 시각·IMU·원본 SHA-256으로 다시 해석한다. 저장된 프로파일을 덮어쓰지 않는다.
실제 세 로그에서 이전 검토 계획과 같은 12개 구간을 확인했다. 이착륙 경계는 제어기 판단 기록이며 물리적 접지 시각이나 정상 상태의 인증은 아니다.
자동 처리가 불명확하면 기존 수동 구간·동기점 보정 흐름을 사용한다. 고정 인덱서는 Python 경로이며 간헐 파서 오류의 원인은 아직 미확정이다.


## 전체 런에서 사용·제외한 시간 (RC12)

새 준비 자료는 원본 검사에서 확인한 시각 범위와 10Hz 입력의 결측 구간을 저장한다.
런 요약의 구간 목록은 겹침 없이 전체 표시 범위를 덮으며, 분석 사용 시간과 미분석 시간의 합은 전체 표시 길이와 같다.
A/B 모델이나 여러 준비 패키지가 같은 시간을 중복 계산하지 않는다. 소스 시각의 마지막 표본은 0.1초 구간으로 표시한다.
분석 요청 범위가 실제 기록보다 길어도 전체 기록 길이는 늘리지 않는다.

미선택/선택 범위 밖은 데이터 결함으로 단정하지 않는다. 입력 누락·오래됨·무효 값과 11초 미만 구간을 별도 표시한다.
파서 절단·시계 역행으로 파일 뒤쪽의 시각을 확정하지 못하면 메모에 근거를 남기고 전체 사용률을 보류한다.
동기점 보정 시각을 원래 로그 전체 범위와 직접 나눠 사용률을 만들지 않는다.

초기 이력은 모델 입력 사용 시간에 포함되지만 건강 판정 점수가 없는 시점일 수 있다. 구간별 실제 관측/점수 수를 함께 읽어야 한다.
