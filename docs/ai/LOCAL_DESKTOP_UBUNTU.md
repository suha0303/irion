# Ubuntu 로컬 실기체 분석 프로그램

2026-11-15 최신 로컬 배포: `ai/releases/drone-local-ubuntu24-20261115-rc16/`.
Ubuntu 24.04 x86_64용이며 Python 3.10.22, PyTorch 2.1.2+cpu, UI 의존성,
최신 forecast 8종/run_health 8종 모델, 빌드된 UI를 포함한다.
원격 GPU·시스템 Python 변경·실행 시 패키지 다운로드가 필요하지 않다.

## 현재 PC에서 로컬 GPU 파인튜닝 실행

RC16은 CPU 분석과 선택형 GPU 파인튜닝을 제공한다. 기존 RC15와 데이터는 보존한다.
이 노트북의 승인된 GPU 환경을 지정하는 명령은 다음과 같다.

```bash
cd /home/sa/CapstoneV3
ARION_DATA_DIR="$PWD/ai/.local/rc13-ui" ARION_PORT=8879 \
ARION_GPU_PYTHON="$PWD/ai/.local/gpu-runtime/bin/python" \
  ./ai/releases/drone-local-ubuntu24-20261115-rc16/drone-local start
```

확인은 `start` 대신 `status`, 종료는 `stop`을 사용한다.
브라우저에서 `http://127.0.0.1:8879`를 열거나 기존 탭을 새로고침한다.

‘로컬 AI · 기체 관리 → 파인튜닝 · 보정 → 기체별 파인튜닝 · 두 모델 함께’에서
forecast/run_health 각 1종, GPU/CPU, 최대 30/60분을 선택한다. 기본은 기존 X500
평가에서 선정한 Transformer h64/l4와 h64/l2다. 전체 16종을 한꺼번에 학습하지 않는다.
준비된 정상 학습 1~3회, 정상 개발 1회, 별도 정상 보정 2회 이상, 정상·이상 평가를
선택한다. 이상 발생 구간과 대상 신호는 확인된 경우에만 입력한다.
알려진 이상을 놓치거나 정상 오차·오경보·검출 지연이 증가하면 적용을 막고,
자료가 부족하면 검증 대기로 남긴다. 성공 후보도 사용자가 명시적으로 적용해야 한다.

현재 노트북에서 기능은 통과했지만 저장된 배터리 이상은 원본과 후보 모두 미탐이다.
새 모델은 활성화하지 않았다. [실측·비교·남은 작업](../development/LOCAL_GPU_G1_G3.md)을 참고한다.
학습 1~3회는 학습 입력 수이며, 신뢰할 수 있는 판정을 확인하려면 별도 검증 자료가 필요하다.

GPU 환경은 배포에 포함하지 않는다. 다른 Ubuntu PC에서는 별도 사용자 환경에
`ai/localflight/requirements-gpu.lock`의 조합을 설치하고 `ARION_GPU_PYTHON`으로
그 Python을 지정한다. 시스템 CUDA·기존 CPU 환경을 덮어쓰지 않는다. 해당 GPU의
드라이버/아키텍처 지원은 별도 확인해야 하며 미확인 장치를 지원한다고 가정하지 않는다.

## 현재 개발 PC에서 검수한 최신 소스 실행

RC15는 실제 로컬 모델 상태와 이상 구간을 주 화면에 연결하고, 기체 관리를 상위 탭과 여섯 작업 메뉴로 나눴다. RC14의 수신·단위·이관 기능을 유지한다.
기존 RC12·RC13·RC14·모델·원자료·검증 증거는 보존했다. `/home/sa/CapstoneV3`의 설치된 환경·모델·빌드된 UI를
사용하려면 다음 명령으로 실행한다.

```bash
cd /home/sa/CapstoneV3
ARION_AI_ROOT="$PWD" \
ARION_DATA_DIR="$PWD/ai/.local/current-ui" \
ARION_PORT=8879 \
./irion-upload/UI/start.sh
```

`http://127.0.0.1:8879`로 접속하고 실행 터미널에서 `Ctrl+C`로 종료한다.
같은 데이터 경로를 지정하면 저장한 기록을 다시 읽는다. 새 폴더에는 기존
앱의 기록을 자동 복사하지 않는다. 모델 목록 확인은 `./ai/drone-ai local catalog`다.
이 진입점의 실제 기동·종료·16종 CPU 실행을 확인했다.
[최신 배포 검증과 남은 항목](../development/CODE_REVIEW_M26_M29.md)을 참고한다.

## 설치와 실행

압축 파일을 원하는 폴더에 풀고, 풀린 폴더에서 실행한다.

```bash
tar -xzf drone-local-ubuntu24-20261115-rc15.tar.gz
cd drone-local-ubuntu24-20261115-rc15
./drone-local doctor
./drone-local start
```

다른 버전의 앱이 같은 포트에서 실행 중이면 새 배포는 성공으로 처리하지 않는다.
기존 앱의 `stop`으로 먼저 종료하거나 아래처럼 다른 포트·별도 데이터 폴더를 사용한다.
기존 데이터를 계속 쓰려면 기존 앱 종료 후 같은 `ARION_DATA_DIR`를 지정한다.

브라우저에서 `http://127.0.0.1:8765`를 연다. 확인과 종료는 다음과 같다.

```bash
./drone-local status
./drone-local stop
```

상위 ‘로컬 AI · 기체 관리’ 탭 안에서 기체 프로파일 → 로그 준비 → 로그 분석 →
파인튜닝·보정 → 모델 보관함 → 작업 결과를 선택한다. 탭 이동 시 입력 중인 값을 유지하며,
작업 결과는 검색·종류 필터 후 하나씩 펼쳐 본다. forecast/run_health 모두 출력층 적응을 제공한다.
메인 화면의 ‘실시간 연결 → 기체별 로컬 AI’에서 기체·예측/종료 후 모델을 선택한다.
‘비행 종료 · 결과 분석’으로 예측·종료 후 모델의 전체 런 결과를 표시한다. ‘이상 구간 분석’에서 기준 초과 시점과 구간별 상세, 사용하지 못한 구간을 확인한다. 실시간 기록 경보와 사후 로그 재분석은 구분해 표시하며, 이전 버전이 저장하지 않은 실시간 이력을 만들어 채우지 않는다. 선택 사항인 ‘시동 해제 확인 시 수집 종료’를 켜면 시동 관측 이후 해제 HEARTBEAT 3개가 2초 이상 이어질 때 자동으로 수집을 닫고 결과를 만든다. 초기 disarmed 상태나 통신 단절만으로 종료하지 않는다. 연결 설정은
`docs/ai/REAL_AIRCRAFT_CONNECTION_GUIDE.md`를 따른다. 자세한 로그 처리 순서는
`docs/ai/LOCAL_REAL_FLIGHT_TIME_HANDLING.md`를 따른다.

기본 데이터 위치는 `${XDG_DATA_HOME:-$HOME/.local/share}/drone-local`이다.
프로그램 폴더는 통째로 이동할 수 있으며 데이터는 프로그램 폴더와 분리된다.
포트나 저장 위치를 지정했다면 start/status/stop에 같은 값을 사용한다.

```bash
ARION_PORT=8878 ARION_DATA_DIR=/your/data/folder ./drone-local start
ARION_PORT=8878 ARION_DATA_DIR=/your/data/folder ./drone-local stop
```

서버는 127.0.0.1에만 바인딩한다. 실행 도구가 생성한 서버 인스턴스인지 확인한 뒤
종료하며, 종료 시 해당 서버의 실행 중 AI 작업도 정리한다. 프로그램 재시작 때 중단된
작업을 자동 재학습하지 않는다. 적응 작업은 마지막 완료 epoch에서 수동 재개할 수 있다.

## 로그에서 프로파일 만들기

1. ‘로컬 AI · 기체 관리 → 로그 준비 → ULog / BIN 가져오기’로 로그를 먼저 검사한다.
   ‘기체 프로파일’로 이동하면 빈 초안에는 명시된 설정을 자동 입력한다. 기존 입력이 있으면 보존하며,
   ‘이 로그로 새 프로파일 초안 열기’로 따로 연다. 과거 검사에는 ‘기존 로그 다시 검사’를 사용한다.
2. ‘분석에 필요한 정보’에는 아직 확인되지 않은 필수 항목과 항상 수정 가능한 셀 수 칸을 표시한다.
   채워진 값은 접힌 수정 화면에서 바꿀 수 있고, 자동 입력에는 로그 파라미터·인스턴스와
   원본 해시를 표시한다. 직접 수정한 항목의 자동 입력 표시는 제거한다.
3. 기체 이름·펌웨어 기록·배터리 식별명·메모는 선택 정보다. ID와 이름은 비우면 생성한다.
   미확인 필수 값이 있어도 프로파일을 저장할 수 있다. 다만 모델 입력 준비는 필요한 값이
   채워져야 한다. 셀 수·용량만 없으면 정규화 전 물리 시계열의 보존 구간 검사는 가능하다.
4. 로그의 설정값은 실제 장착 부품을 확인한 값과 구분한다. 파라미터 변경·다중 센서·미지원
   매핑은 자동 확정하지 않는다. 셀 수는 충분한 전압 근거가 있으면 추정값을 미리 채우고 바로 수정할 수 있게 한다. 건강 상태는 정상으로 지정하지 않는다.

2026-11-14 실제 BIN 3개에서는 주요 입력 필드와 단위를 확인했다.
사용자 승인에 따라 RC10부터 세 로그 모두 셀 수 12S를 전압 기반 추정으로 자동 입력한다.
`00000005.BIN`은 추정기 코어가 전환되어 사용할 IMU/보존 구간 선택이 필요하다.
공통 용량 44 Ah는 `BATT_CAPACITY=44000`이라는 기록된 설정값이다.
추정은 4.2 V급 리튬계 가정 아래 실측 전압과 모터 보상 전압 상·하한, 배터리 저전압·위험 전압을 함께 대조한다. 하나의 후보가 남을 때만 입력하며 추가 확인 버튼 없이 저장·분석에 사용할 수 있다. 실물 확정값이나 배터리 종류 자동 판별을 뜻하지 않는다. 수정한 값은 기존 저장 버전을 덮어쓰지 않는다.
PX4는 명시적인 셀 수·용량 등만 읽고, 출력 위치/범위가 확정되지 않으면 직접 확인하도록 남긴다.

## 예측 결과와 모델 관리

분석 결과는 신호별 RMSE, 직전값 유지 기준의 RMSE, 처리 시간, 기록 사용률을 표시한다.
시계열 그래프는 **1초 앞 예측과 그 시각의 실측**, 잔차(실측−예측)를 표시한다.
표의 RMSE는 0.1~1초 전체 예측 시점 기준이다. 구간 사이의 선을 연결하지 않는다.
기체별 임계값을 보정하기 전 정상 경보율은 수치로 제시하지 않는다. 보정 후에도 독립 정상 평가의 관측별 초과율과 비행 단위 오경보율을 구분한다.

1. 완료된 적응 작업을 ‘모델 보관함에 등록’한다. 가중치·scaler·프로파일·계보 해시를 묶는다.
2. 학습/모델 선택에 쓰지 않은 독립 평가 비행으로 비교한다. 단순히 같은 비행을 잘라서는
   독립 평가가 되지 않는다. 오차 개선과 건강 판정 성능은 별개다.
3. 비교 결과를 확인하고 ‘이 기체의 분석 모델로 선택’을 누른다. 선택은 기체 프로파일 버전과
   원본 모델별로 저장되며, 원본 가중치를 덮어쓰지 않는다.
4. 5번 분석 화면에서 ‘선택한 적응 모델 사용’을 켠다. 선택 기록이 없는 조합은 원본을 사용하며,
   결과에 원본/적응 가중치 식별자를 표시한다.
5. ‘이전 선택으로 원복’하면 직전 선택으로 돌아간다. 최초 선택을 원복하면 원본 모델을 사용한다.

‘백업 파일 만들기 → 다운로드’는 실행 코드와 원시 로그가 없는 ZIP을 만든다.
가져오기는 64 MiB 제한, 파일 목록/해시, 가중치 이름·형상·유한값, 고정 인코더/scaler,
CPU forward를 검사한다. 다른 PC로 가져온 모델은 자동으로 선택되지 않는다.
기체 프로파일과 출처가 맞는 독립 비교를 다시 거쳐 선택한다. 이는 암호학적 서명에 의한
배포자 인증이 아니라 파일 무결성과 모델 구조 확인이다.

## 사용자 데이터 폴더 복사 이관

RC13은 최신 파일 저장 형식의 `ARION_DATA_DIR` 전체를 **새 경로로 복사**한다.
프로그램을 먼저 종료하고 실행한다. 원본은 삭제하거나 덮어쓰지 않는다.

```bash
./drone-local migrate-data --source /old/data --destination /new/data
ARION_DATA_DIR=/new/data ARION_PORT=8879 ./drone-local start
ARION_DATA_DIR=/new/data ARION_PORT=8879 ./drone-local status
ARION_DATA_DIR=/new/data ARION_PORT=8879 ./drone-local stop
```

원시 로그·프로파일·모델·scaler·보정값·체크포인트·출처 해시는 그대로 복사한다.
카탈로그·작업·실시간 세션의 운영 경로만 갱신하고, 변경 전 메타데이터와 파일별
SHA-256 보고서를 새 폴더의 `.migrations/`에 보존한다. 중단된 작업은 자동 실행하지
않으며, 적응 작업은 UI에서 수동 재개한다. 같은 데이터 폴더를 두 앱이 동시에 사용할 수 없다.

대상은 존재하지 않는 폴더여야 한다. 외부 파일 참조·심볼릭 링크·실행 중 앱이 있으면
이유를 표시하고 중단한다. 실패한 복사본은 미완료 표시를 남겨 앱이 열지 못하게 한다.
원인을 해결하고 다른 새 폴더로 다시 실행한다. 과거 SQLite만 있는 데이터는 현재 앱으로
파일 저장 형식으로 변환한 뒤 이관한다. 개발 환경에서 별도로 저장했던 AI 데이터와 UI
데이터를 자동 합치는 기능은 아니다. 기체별 모델만 다른 PC로 옮길 때는 모델 ZIP을 쓴다.

## 확인된 실행 범위

- RC13 배포 Python: 관련 AI 101개·UI 백엔드 106개 통과. UI 26개·빌드 통과.
  후보의 프로젝트/네트워크 격리 실행과 16종 CPU forward, 프로파일/이관 API를 확인했다.
  최종 아카이브의 해시·압축 해제 검증은 옆의 `.sha256`, `.release.json`에 기록한다.
- RC13은 PX4 수직 속도 유효성·전류 미측정·출력 개수 검사와 배포 워커의 선택적
  원격 모듈 의존성을 수정했다. 기존 전압 예측 정확도 문제를 해결했다는 뜻은 아니다.
- 합성 256 MiB ULog 검사에서 CPU 1개/주소공간 1.5 GiB 제한으로 최대 RSS 약
  288.5 MiB를 측정했다. 실제 고밀도 비행 데이터의 최소 사양 보증은 아니다.

- Ubuntu 24.04, Intel Core i7-14700HX, RAM 약 16 GB 개발 PC에서 확인했다.

## 개발자가 패키지를 다시 만들 때

기존 AI 환경을 보존하고 추가 UI 의존성은 별도 폴더로 설치한다.

```bash
ai/.venv/bin/python -m pip install \
  --target ai/.local/desktop-build/ui-packages \
  -r ai/localflight/requirements-desktop-ubuntu.lock
```

frontend 디렉터리에서 `npm run build` 후 프로젝트 루트에서 새 출력 폴더로 빌드한다.

```bash
PYTHONPATH=ai:ai/src:Data/generation ai/.venv/bin/python \
  -m localflight.distribution build --output ai/releases/NEW_RELEASE
```

기존 패키지 경로를 덮어쓰지 않는다. `APP_MANIFEST.json`에 실행 파일 해시,
`DEPENDENCIES.lock`에 전체 설치 버전, `MODEL_CONTENTS.json`에 원본 모델 manifest와
포함된 파일 목록을 기록한다. 원래 전달본 manifest는 수정하지 않고 보존하되,
대용량 평가 예측 배열·실기체 원본 로그·사용자 프로파일/인증 정보는 패키지에 포함하지 않는다.

RC1의 Python 3.10 `hashlib.file_digest` 호환성 실패와 uvloop 누락 시험 기록은 보존했다.
RC3부터 순차 SHA-256 구현 및 uvloop 0.23.0을 포함한다. 기존 Python 3.12 UI 환경도
동일 회귀 시험을 통과했으며 원래 AI venv는 수정하지 않았다.

RC5에는 기체별 실시간 CPU 추론·명시적 종료 후 분석·run_health 출력층 적응이 포함된다.
RC4에서 발견한 사용자 지정 포트 WebSocket Origin 오류를 수정했다. 이전 릴리스 경로로 실행하면
최신 기능이 나타나지 않으므로 기존 앱을 종료하고 최신 RC13을 실행한다. 사용자 데이터는 같은 기본 폴더를 사용한다.


## RC8 기체별 보정과 판정

RC8은 임계값 보정·정상 범위/이상 의심/판정 불가·메시지 주기 자동 설정을 추가한다.
기존 앱이 켜져 있으면 그 앱을 종료한 뒤 RC8을 시작해야 새 기능이 표시된다.

1. 모델 학습은 기존대로 정상 비행 1~3회로 수행한다. 그 뒤 **학습·모델 선택과 다른 정상 비행 2~20회**를
   자료 용도 ‘임계값 보정’으로 준비한다. 불명확한 건강 상태를 정상이라고 가정하지 않는다.
2. ‘기체별 임계값 보정’에서 모델 A와 보정 자료를 선택한다. 파인튜닝 사용을 켜면 채택된 기체별 모델,
   없으면 원본을 보정한다. 비행별 경험적 백분위를 구한 뒤 비행 간 백분위로 기준을 만든다.
3. 예측 모델은 비행별 최소 20개의 유효한 1초 앞 예측/실측 쌍이 필요하다. 종료 후 모델은 구간별
   전압 잔차 지표를 사용한다. 연속 창 개수를 독립 비행 횟수로 계산하지 않는다.
4. 생성된 버전의 ‘판정에 사용’을 누른다. 이전 보정값 재선택·적용 해제가 가능하다.
   원본 모델과 보정값은 덮어쓰지 않는다. 백분위 99%는 실제 오경보율 1% 보장이 아니다.
5. **별도 평가 비행**을 분석한다. 보존된 관측에 기준 초과가 없으면 정상 범위, 있으면 이상 의심이다.
   학습·보정 비행 재사용, 일치하는 보정값 없음, 입력 부족은 판정 불가다. 독립 정상으로 확인한 자료만
   관측별 기준 초과율을 표시한다. 실제 탐지율·오경보율은 실기체 독립 자료로 검증해야 한다.

온보드 로그와 실시간 수신 기록은 다른 시계/전처리 경로이므로 보정값을 구분한다. 실시간용 보정은
비행 종료 결과의 ‘수신 기록을 학습·보정·평가 자료로 등록’에서 정상 근거를 입력해 준비한다.
분리된 구간을 같은 원본 비행에서 가져와 여러 독립 비행으로 세거나 학습/보정에 중복 사용하지 않는다.
원시 비행 전체의 상태가 미확인이면 등록도 미확인으로 유지한다.

실시간 설정의 자동 주기 요청은 기본 활성화되며 끌 수 있다. ACK·설정 조회·실수신률은
메인 카드의 ‘메시지 주기 설정’에서 확인한다. 종료 버튼은 수신·분석 종료이며 기체 제어 명령이 아니다.


RC6에서 Python 3.10 기본 이벤트 루프의 UDP 송신 API 미지원으로 시험 2건이 실패했다.
RC7은 비차단 소켓 송신으로 수정해 87건을 통과했다. RC7 압축 중 시험이 생성한 바이트코드와
경합한 실패 아카이브도 보존했다. RC8은 종료 뒤 ‘분석 중’ 표시 잔류를 수정하고,
바이트코드 생성을 끈 패키지 시험 및 압축 설치 검증을 적용한 배포 후보다.

## RC12 전체 런 요약

로그 파일 하나 또는 실시간 수집 세션 하나를 하나의 런으로 표시한다. 한 파일에 여러 이착륙이 있으면 같은 원본의 구간으로 묶인다.

- 로그: 준비된 비행을 선택하고 ‘같은 원본의 다른 준비 구간 함께 분석’에서 추가할 구간을 체크한 뒤 ‘선택 모델 A/B로 분석’을 누른다. 중복·겹친 구간은 선택을 다시 요청한다.
- 실시간: 수동 또는 선택형 시동 해제 종료 후 전체 런 요약이 자동 표시된다. 분석 가능한 구간이 없어도 제외 이유를 표시한다.
- 요약: 실제 기록 범위, 분석 입력 사용 시간, 미분석 시간, 전체 사용률, 모델별 합산 오차와 구간 판정 수를 표시한다.
- ‘분석·미분석 구간과 제외 이유’에서 시간 구간·사유를 확인하고 ‘미분석 구간만 보기’로 좁힐 수 있다.
- ‘구간별 상세 결과’를 펼치면 구간별 판정과 수치를 볼 수 있고 예측 모델은 시계열 그래프도 제공한다.

선택하지 않은 범위는 ‘선택 범위 밖’, 누락/오래됨/무효 입력은 해당 입력 목록과 함께, 연속 11초 미만은 짧은 구간으로 표시한다.
기록이 없는 구간을 정상으로 채우지 않는다. 전체 정상 인증을 제공하지 않으며 일부 구간에서 이상 의심이 있으면 그 사실을 표시한다.
분석 입력 사용 시간에는 초기 이력이 포함된다. 실제 점수 산출 시점 수와 같지 않다. 전체 사용률과 개별 준비 범위의 사용률을 구분한다.

이전 결과는 자동으로 덮어쓰지 않는다. 이전 준비 자료를 다시 분석하면 새 요약을 볼 수 있지만 원본 전체 시각을 저장하지 않았던 자료는 사용률이 ‘범위 미확정’이다.
로그를 다시 검사하고 구간을 새로 저장하면 전체 기록 범위를 포함한다. 시계 역행·보정으로 전체 시각 범위를 확정하지 못하면 전체 사용률을 산출하지 않는다.

## 이번 PC의 시연 데이터로 실행

시연에 사용한 BIN 분석·기체 프로파일·PX4 수신 기록은 같은 데이터 폴더에 유지한다.
다른 버전이 이 포트에서 실행 중이면 해당 버전의 `stop`을 먼저 사용한다.

```bash
cd /home/sa/CapstoneV3
ARION_DATA_DIR="$PWD/ai/.local/rc13-ui" ARION_PORT=8879 \
  ./ai/releases/drone-local-ubuntu24-20261115-rc15/drone-local start
```

브라우저 주소: `http://127.0.0.1:8879`. 종료도 같은 환경과 경로의 `stop`을 사용한다.

RPM은 FC가 보낸 ESC_STATUS에 포함된 실제 값을 표시한다. 현재 수집용 PX4/Gazebo는
ESC 피드백을 전송하지 않으므로 `ESC RPM 미수신`으로 표시한다. 원시 정답의
모터 각속도나 PWM을 RPM 관측값으로 대입하지 않는다. RPM은 공통 19개 AI 입력에
포함되지 않으며 필수 입력이 유효하면 RPM 없이도 추론할 수 있다.

실시간 원본 기록은 최대 100 ms/1 MiB 묶음으로 별도 저장한다. 종료 시 fsync까지
확인한다. 전원 차단 시 미동기화 묶음은 유실될 수 있으며, 저장 지연으로 16 MiB
버퍼를 초과하거나 디스크 오류가 발생하면 수집 오류를 표시한다.
