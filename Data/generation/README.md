# 데이터 생성 코드

- `drone-data`: 환경 설치·진단·소스 export·수집 메뉴의 공통 진입점.
- `drone-pretrain`: 설치 후 같은 수집·전처리 메뉴를 직접 여는 명령.
- `pretrain/`: 구성·seed·선택 게이트·수집·추출·전처리·공통 scaler 집계·독립 검산·압축·진행 화면.
- `tools/`: 기존 finite collector와 공유 프로세스·압축·검증 도구.
- `pretrain/resources/`: 현재 수집 템플릿·건강 조건·동결 전처리 패키지.
- `.venv/`: 설치 명령으로 생성하는 Python 3.12 CPU 처리 환경. Git에 넣지 않는다.

```bash
./Data/generation/drone-data setup --simulation
./Data/generation/drone-data doctor
./Data/generation/drone-data menu
```

프로젝트 루트에서 위 명령을 실행한다. 스크립트가 실제 설치 위치에서 프로젝트를 찾으므로 사용자 이름이나 `/home/sa/CapstoneV3` 경로를 맞출 필요가 없다. 실행에 필요한 Python 경로는 자동 설정한다. 공통 전처리 알고리즘과 모델 입력 계약은 `../../ai/src/capstone_ai/`를 재사용하고 학습용 GPU 환경은 변경하지 않는다. 자세한 사전 조건은 [설치 안내](../../docs/data/PORTABLE_SETUP.md)를 따른다.

작업 상태·로그는 프로젝트 `Data/operations/pretrain/`에 저장하고 최종 데이터는 메뉴에서 선택한 저장소에 둔다. 세부 설정과 실패·재시도 정책은 [수집 안내](pretrain/README.md)를 따른다. 게이트는 선택 사항이고 비행16/나머지4가 기본이다. 장시간 반복은 Python/셸 실행기가 맡으며 LLM 호출은 없다.

## MAVLink 원문 수집

```bash
./Data/generation/drone-pretrain mavlink \
  --out Data/streamed/mavlink/batch-01 --count 16 --duration 90
```

처음 시작할 때는 새 배치 폴더를 지정한다. MAVLink 원문 수집의 병렬 비행은 기본 16개이며 최대 64개를 지정할 수 있다. 인스턴스별 MAVLink 수신 포트는 `14700+인스턴스`다. `--count`는 배치의 완주 목표다. `--flight-workers`로 동시에 실행할 비행 수를 지정하고, `--scenario`, `--seed`, `--duration`으로 실행 조건을 정한다. `--real-time-factor`를 생략하면 시뮬레이션 속도를 1배로 요청한다.

Gazebo 메시지 탐색 포트는 `24100+인스턴스`, 서비스 탐색 포트는 `24200+인스턴스`를 사용한다. 같은 비행의 PX4·Gazebo와 종료 클라이언트가 이 포트쌍을 공유하며, 다른 비행에는 별도 포트쌍을 할당한다. 각 비행의 `request.json`에 할당을 남긴다.

인스턴스 32~63의 비행 제어에는 PX4 측 `19100+인스턴스`와 실행기 측 `19000+인스턴스`를 사용한다. 이 범위의 비행 제어 포트는 인스턴스 0~31의 기존 제어 포트와 겹치지 않는다.

비행 수신기는 프로세스당 최대 8개씩 분산한다. 32병렬에서는 수신 프로세스 4개가 각 비행의 UDP를 독립적으로 받아 파일에 기록한다.
각 슬롯은 시뮬레이터를 종료하고 UDP 수신을 마쳐 파일과 소켓을 닫으면 즉시 다음 비행을 시작한다. 다음 비행은 같은 슬롯의 포트를 사용한다. 이전 프로세스의 종료가 확인되지 않은 슬롯은 이번 배치에서 재사용하지 않는다.

i7-14700HX에서 180초 X500 호버 시험의 실제 비행 배속 중앙값은 32병렬에서 0.997배, 64병렬에서 0.658배였다. 이 호스트에서 1배속에 가깝게 64건을 수집하려면 `--count 64 --flight-workers 32`로 실행한다. 64개를 동시에 1배속으로 수집하려면 CPU 여유가 있는 장비에 작업을 분산하고 각 장비에서 실제 배속을 확인한다. 장비마다 출력 경로와 시드 범위를 따로 지정한다.

- `flight-0001/datagrams.bin`에는 수신한 UDP 바이트를 그대로 보관한다. 첫 8바이트는 `MLUDP001`이며, 각 데이터그램은 빅엔디언 수신 단조 시각(ns), UTC 시각(ns), IPv4 주소 4바이트, 발신 포트, 바이트 길이, 원문 순서다. 시각은 각 64비트이고 포트와 길이는 각 16비트다.
- 비행 시작 전에 소켓을 연다. 시뮬레이터 종료 후 수신이 100ms 동안 없을 때 소켓을 닫는다. 이륙 전과 착륙 후에 수신한 데이터그램도 수신 순서대로 보관한다. MAVLink 메시지 해석과 JSONL 변환은 수집 단계에서 수행하지 않는다.
- `collection.json`에는 각 시뮬레이션의 종료 상태를 남긴다. 실패한 비행의 수신 바이트도 해당 비행 폴더에 보관한다. PX4 uORB 캡처, ULog와 시뮬레이터 내부 시계열 기록은 이 모드에서 비활성화한다.

### 중단 및 재개

수집 터미널에 전체 목표 대비 완주 건수, 실패 시도, 진행 중·대기 건수와 예상 남은 시간을 표시한다. 슬롯마다 비행 번호·시드·임무 경과/목표 시간·배속·상태, 기동·바람·배터리와 추진계 열화 단계를 볼 수 있다. 작은 터미널에서는 `n`으로 다음 슬롯 화면, `b`로 이전 화면을 연다. 예상 시간은 각 비행 시간, 동시 실행 수, 관측된 시뮬레이션 배속을 반영한다.

수집 중 같은 터미널에서 `p`를 누르면 즉시 새 비행 배정을 멈춘다. 화면에는 진행 중인 비행 수와 그 비행들이 모두 착륙하고 UDP 기록을 저장하기까지의 예상 시간이 표시된다. 최종 결과가 표시되고 명령이 종료되면 컴퓨터를 꺼도 된다.

```bash
./Data/generation/drone-pretrain mavlink --out Data/streamed/mavlink/batch-01
```

같은 출력 경로를 지정하면 `batch.json`에서 최초 옵션과 시드 범위를 불러온다. 비행별 `flight.json`과 기록 파일을 기준으로 완주 시드를 확인하고 부족한 건수만 시작한다. 실패·미완주 폴더는 보존하고, 최초 범위에서 아직 완주하지 않은 시드를 새 비행 번호로 실행한다. 시도 중 실패가 생겨 목표에 못 미치면 같은 명령으로 다시 보충한다. `batch.json`이 있는 수집 폴더를 재개할 수 있다.

### 1,600건 MAVLink 학습 입력 준비

수집한 정상 학습 1,000건, 정상 보정 150건, 최종 정상 250건, 최종 이상 200건을 이륙·착륙 포함 10초 버퍼 전처리로 변환한다. `--profile`에는 PX4 X500 4S·12 Ah, 모터 및 센서 매핑이 확인된 JSON 프로파일을 지정한다.

```bash
./Data/generation/drone-pretrain mavlink-prepare \
  --capture-root Data/streamed/mavlink \
  --out Data/processed/new19-mavlink-buffered-20261120 \
  --profile "$X500_MAVLINK_PROFILE" --workers 4
```

비행별로 별도 Python 프로세스에서 만들고, 검증된 출력 파일과 영수증을 완료 폴더에 함께 저장한다. 같은 원문·프로파일·출력 경로로 재실행하면 저장한 계획과 해시를 확인해 완료한 비행을 건너뛴다. 재개 시 `--workers`는 1~32 범위에서 바꿀 수 있다. 작업 프로세스가 중간에 종료되면 해당 비행을 재시도하며 실패 기록은 `.attempts`에 남긴다. `progress.json`에 실행 상태를, `summary.json`에 분할별 비행 중 예측용·전체 런용 입력 적격성과 비행별 근거를 기록한다. UDP 원문은 수집 폴더에 보존한다.

추가로 수집한 `normal-validation-01` 150건은 `--validation-only`를 붙이고 별도 `--out`을 지정해 같은 프로파일로 전처리한다. 학습 매니페스트에는 기존 정상 학습용 1,000건을 `normal_train`, 추가 150건을 `normal_validation`으로 지정한다.

### 정상 학습용 무작위 비행

```bash
./Data/generation/drone-pretrain mavlink --normal-random \
  --out Data/streamed/mavlink/normal-training-01 --count 32
```

`--normal-random`은 기본 동시 실행 수 32개와 1배속을 사용한다. 추가 하중 0g, 외기 25°C, 시작 SOC 90%를 사용한다. 각 인스턴스의 실행 요청을 만들 때 시드로 5~15분의 임무 길이와 단일·복합·연속 무작위 경로 유형을 독립적으로 뽑는다. 단일 경로는 기본 기동 중 하나를 고르고, 복합 경로는 여러 기본 기동의 순서를 무작위로 섞는다. 무풍·약풍·강풍과 풍향·변동 강도도 비행마다 뽑는다. 각 비행에 쓰인 시드와 조건은 해당 `request.json`에 기록한다.

정상·이상 무작위 모드의 새 배치는 `--seed`를 생략하면 시작 시드를 무작위로 뽑는다. 같은 상위 폴더에 저장된 다른 배치와 전체 시드 범위가 겹치지 않는 곳을 고른다. 재개할 때는 해당 폴더의 `batch.json`에 저장한 시드 범위를 사용한다.

### 이상 데이터용 무작위 비행

```bash
./Data/generation/drone-pretrain mavlink --abnormal-random \
  --out Data/streamed/mavlink/abnormal-collection-01 --count 32
```

정상 학습용과 같은 길이·경로·바람 및 초기 운용 조건을 사용한다. 단일 또는 복합 열화를 각각 50% 확률로 고른다. 단일 열화는 배터리와 추진계 중 하나를 고른다. 선택된 계통마다 4·8·12·16 중 하나를 뽑고 이륙 전부터 그 단계로 비행한다. 배터리는 기존 CMU VAH01의 해당 RPT 프로파일을 사용한다. 추진계 4·8·12단계는 정상과 기존 최대 열화 프로파일 사이의 25·50·75% 선형 보간이고, 16단계는 기존 최대 열화다. 각 비행의 열화 단계는 `request.json`과 시뮬레이터의 `evaluation/scenario.json`에 기록한다.
