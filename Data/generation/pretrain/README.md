# 드론 학습 전 수집·처리 콘솔 (기본 X500)

프로젝트 루트에서 `./Data/generation/drone-data menu` 또는 `./Data/generation/drone-pretrain`을 실행한다. 새 컴퓨터의 환경 설치·진단은 [설치 안내](../../../docs/data/PORTABLE_SETUP.md)를 따른다.

메뉴는 새 수집, 유한한 시험, 기존 작업 화면, 작업 종료를 제공한다. 실제 수집과 시험은 사용자가 실행한다. 화면은 프로그램이 갱신하며 LLM 호출은 없다. q/Ctrl+C는 화면만 닫는다.

기체를 따로 지정하지 않으면 X500이다. 이 데이터·AI 인수 경로는 현재 X500 전용이며, 다른 기체의 시험은 시뮬레이션 CLI에서 명시적으로 선택한다.

현재 기본값은 balanced300 구성1배율, 비행16병렬, 검증·압축/추출/전처리/품질 검산 각각4병렬, 2배속이다. 비행 수는 PX4 인스턴스 계약상1..16이며 CPU 처리 수는 양의 정수를 받는다. 메모리 추정 차단/고정 RSS 상한은 기본 해제지만 최소 가용 RAM1GB와 프로그램 안전 검사는 유지한다. swap은 기본 허용한다. 게이트는 선택시에만 수행한다.

정상 조건 범위·조합과 경로를 다양하게 생성한다. 저SOC는3분, 일반 정상은15분을 기본으로 하며 이상과 정상 대조는 별도 역할을 유지한다. 세부 분할은 `balanced.py`의 실제 구성과 생성된 작업 manifest가 기준이다. seed 기본값은 작업마다 OS 난수에서 정하며 `--seed-base`로 재현 가능한 값을 직접 지정할 수 있다. 수집 seed와 모델 학습 seed는 별개다.

선택한 배율 전체를 하나의 데이터셋으로 만들고 정상 train만 사용한 공통 scaler를 저장한다. 흐름은 선택 게이트 → 수집과 유한 묶음별 추출·전처리 → 전체 집계 → 독립 검산 → 최종 패키지 검증 → 정지다. 기본 stream_compact는 성공 산출물의 해시 검증 후 해당 작업 소유의 성공 원시·중간 파일만 정리한다. 실패 증거는 보존한다. 개별 안전 실패의 재시도는 최대2회(총3회)이며 자원 장애·사용자 종료 등에는 기존 실패 정책을 따른다. 불완전한 전체 구성을 정상 학습 데이터로 인수하지 않는다.

현재 수집은 연속 무작위 경로 전체를 덮는 충돌 지면과 0.3m/s 착륙 속도를 사용한다. 착륙 속도는 실제 PX4 응답과 producer 봉인으로 검증하며, 과거 run은 당시 봉인의 정책으로 검산한다. 비행 명령이 실패하면 해당 run의 ID·실제 단계·종료 사유를 함께 남긴다. 이 수정 전 작업은 소스가 고정돼 있으므로 변경된 실행기를 적용하려면 새 수집 작업을 만든다. 기존 성공·실패 자료를 덮어쓰지 않는다.

작업 기록: 프로젝트 `Data/operations/pretrain/tasks/<task>/operator/state.json`, `operator/run.log`.

기본 저장소: 현재 프로젝트의 `Data/`.

수집·정제 Python은 `Data/generation/.venv`, 네이티브 시뮬레이션 Python은 `simulation/.venv`다. 시뮬레이션 소스·프로필은 `simulation/sim/`, `simulation/profiles/`, 소스 잠금은 `simulation/config/producer-sources.json`, 설치별 runtime 식별은 `simulation/artifacts/runtime-manifest.json`을 사용한다. `ai/.venv`나 GPU 설치는 수집·정제를 위해 사용하지 않는다.

코드와 소스 잠금, 설치 환경, 작업별 isolation 증거는 새 작업을 만들 때 고정한다. 오래된 회차 디렉터리나 다른 장비의 바이너리·mount 기록을 새 수집의 준비 조건으로 재사용하지 않는다. 데이터 계약과 동결 전처리 내용은 보존하며 기존 자료의 provenance는 수정하지 않는다.

작업 소유권·인스턴스/수집 잠금, 실제 실행 중인 작업 파일은 임의로 지우지 않는다. 수집·전처리 성공이 학습·평가 완료를 의미하지 않는다. 이 콘솔은 본학습을 자동 시작하지 않는다. 과거 운영 기록과 실측 보고서는 로컬 보존 자료로 유지하며 소스 배포에 포함하지 않는다.

## 저장 위치 선택

메뉴의 `최종 데이터 저장 폴더`에 경로를 입력한다. 빈칸은 프로젝트 루트의 `Data/`다. 명령행에서는 `init --storage-root /원하는/저장폴더`로 지정한다. 선택한 경로에 `archives/`, `consumer/`, `streamed/`, `processed/`, `speed-tests/`가 필요에 따라 생성된다. 최종 압축 데이터셋은 `processed/pretrain/<task>/prepared-portable/`다. 기본 stream_compact에서는 검증된 성공 원시·중간 파일을 처리하며 정리하고 실패 증거는 유지한다. 로컬 실행·운영 로그는 프로젝트 `Data/operations/pretrain/`에 둔다.

저장 경로와 파일시스템은 새 task 설정에 고정되고 systemd와 CPU 하위 프로세스에 전달된다. 이미 생성된 task의 저장 위치는 변경하지 않는다. 외장 저장소를 직접 선택할 수 있으며, 선택한 장치가 사라지거나 바뀌면 실패로 멈추고 다른 디스크로 자동 전환하지 않는다. 외장하드 연결 없이 기본 로컬 경로를 사용할 수 있다. 로컬 실행·운영 로그는 프로젝트 `Data/operations/pretrain/`에 둔다.

실제 코드는 `Data/generation/pretrain/`이다. 원본 입력과 출력의 symlink 보호를 유지하고 작업별 소스 잠금에는 실제 경로를 기록한다. 시뮬레이션 원본 잠금 키는 `simulation/` 기준이다. 시뮬레이터 원시 임시 run은 `simulation/runs/`, 최종 데이터는 선택한 저장 루트의 `processed/` 아래에 있다.
