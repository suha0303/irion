# ARION V0.2 · 드론 비행 분석

PX4·ArduPilot 비행 로그와 MAVLink 수신 데이터를 분석하는 오프라인 데스크톱 앱입니다. 비행 중 예측 4종과 비행 후 판정 4종을 기본 제공하며, 설치 후 CPU에서 실행합니다.

## 설치

[GitHub Releases에서 ARION V0.2.0-rc.3 받기](https://github.com/suha0303/irion/releases/tag/v0.2.0-rc.3)

| 운영체제 | 설치 방법 | 검증 환경 |
| --- | --- | --- |
| Ubuntu x64 | `.deb`와 `.sha256`을 받은 뒤 아래 명령으로 설치합니다. 앱 메뉴에서 **ARION**을 엽니다. | Ubuntu 24.04.5 노트북 |
| Windows x64 | `.exe`를 실행한 뒤 시작 메뉴에서 **ARION**을 엽니다. 설치본에는 코드 서명이 없습니다. | Windows Server 2025 GitHub Actions |
| macOS | Apple Silicon은 `macos-arm64.dmg`, Intel은 `macos-x64.dmg`로 끝나는 파일을 받습니다. DMG를 열고 ARION을 Applications로 옮깁니다. | macOS 15 GitHub Actions |

```bash
sha256sum -c ARION-0.2.0-rc.3-ubuntu-amd64.deb.sha256
sudo apt install ./ARION-0.2.0-rc.3-ubuntu-amd64.deb
```

Windows 설치본은 `Get-FileHash .\ARION-0.2.0-rc.3-windows-x64.exe -Algorithm SHA256`으로 첨부된 `.sha256`과 대조할 수 있습니다. 자세한 절차는 [설치 안내](docs/ai/DESKTOP_RELEASE.md)와 [검증 체크리스트](docs/ai/ARION_RELEASE_CHECKLIST.md)에 있습니다.

Mac DMG는 Apple 공증 전 테스트용입니다. 같은 폴더에 DMG와 해당 `.sha256`을 두고 `shasum -a 256 -c ARION-0.2.0-rc.3-macos-arm64.dmg.sha256`을 실행합니다. Intel은 파일명에서 `arm64`를 `x64`로 바꿉니다. 해시가 일치하고 첫 실행이 차단되면 **시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기**에서 ARION에 예외를 줄 수 있습니다. [Apple 첫 실행 안내](https://support.apple.com/ko-kr/102445)

## 사용 방법

### 1. 비행 로그 분석

MAVLink 연결 없이 저장된 PX4 `.ulg` 또는 ArduPilot `.bin` 파일을 분석할 수 있습니다.

1. **로그 모니터링 → 비행 로그 가져오기**에서 파일을 엽니다. 검사 후 **비행 로그 선택**에서 원본을 고릅니다. 재생 막대로 관측값, 배터리 추이와 위치·궤적을 확인할 수 있습니다. 각 항목은 로그에 필요한 신호가 있을 때 표시됩니다.
2. **로그 검사 · 구간 준비**를 엽니다. 같은 기체의 저장된 프로파일이 있으면 선택하고, 처음이면 **이 로그로 프로파일 만들기**를 누릅니다. 로그에서 채운 비행제어기, 배터리 직렬 셀 수·용량, 모터 채널·출력 범위, IMU·배터리·출력 인스턴스를 확인합니다. 빈 값이나 추정으로 표시된 항목은 기체 설정이나 로그를 확인해 수정하고 **새 버전으로 저장**을 누릅니다. V0.2 기본 모델의 입력은 4로터 구성입니다.
3. 확인할 구간의 시작·종료 시각을 선택합니다. 자동 구간이 있으면 범위를 확인하고, 직접 지정하려면 **시작 (초)**과 **종료 (초)**에 부팅 후 시각을 입력합니다. **사용 가능 구간 찾기**를 누르면 기록 공백을 기준으로 나눈 구간이 표시됩니다. 11초 이상인 사용 가능 구간을 선택하고 **비행 중 구간 선택 근거**를 작성합니다. 일반 분석은 비행 용도 **독립 평가·예측**을 선택합니다. 정상 여부를 모르면 건강 상태를 **모름**으로 두고 **선택 구간 저장**을 누릅니다.
4. **로그 모니터링 → 새 분석 실행**으로 돌아갑니다. 준비한 구간과 모델을 선택한 뒤 **선택한 모델로 분석**을 누릅니다. 모델 하나, 비행 중 예측 4종, 종료 후 판정 4종, 전체 8종을 선택할 수 있습니다. 같은 기체의 파인튜닝 결과가 있으면 **이 비행의 모델과 판정 기준**에서 후보를 선택해 분석할 수 있습니다.
5. 완료되면 같은 화면의 **비행 후 판정**과 **실측·예측·이상 점수 그래프**를 봅니다. 분석을 여러 번 했다면 결과 목록에서 원본과 후보 결과를 바꿔 볼 수 있습니다. 작업 진행 상태와 오류는 **로컬 AI · 기체 관리 → 작업 결과**에서도 확인할 수 있습니다.

### 2. 실시간 비행 연결

V0.2의 실시간 AI 분석 경로는 **PX4 MAVLink UDP**입니다. ArduPilot 실기체는 위의 BIN 파일 분석 절차를 사용하세요. 실시간 분석과 시뮬레이터 통신 시험은 같은 화면에서 연결 대상을 선택합니다.

1. **로컬 AI · 기체 관리 → 기체 프로파일**에서 연결할 기체의 프로파일을 등록합니다. 기존 로그에서 만든 같은 기체의 프로파일도 사용할 수 있습니다. 출력 채널과 범위는 연결할 기체 설정을 확인해 입력합니다.
2. PX4 또는 텔레메트리 라우터가 ARION을 실행하는 PC로 MAVLink UDP를 보내도록 설정합니다. 같은 PC의 SITL은 대상 주소로 `127.0.0.1`을, 별도 장비는 ARION PC의 LAN IP를 사용합니다. 아래와 같이 송신 대상과 ARION 수신 포트를 맞춥니다.

   | 항목 | 같은 PC에서 PX4 SITL 연결 예시 |
   | --- | --- |
   | PX4의 UDP 송신 대상 | `127.0.0.1:14560` |
   | ARION의 UDP 수신 주소 | `127.0.0.1` |
   | ARION의 전용 UDP 포트 | `14560` |

3. **실시간 비행 모니터링 → 실시간 연결**에서 **MAVLink UDP**를 선택하고 주소와 포트를 입력한 뒤 **수집 시작**을 누릅니다. 수집 건수가 증가하는지 확인합니다. 같은 포트를 다른 프로그램이 사용 중이면 비어 있는 포트를 정해 송신기와 ARION 양쪽을 맞춥니다.
4. **이 비행의 모델 선택**을 열어 **기체 프로파일**, **연결 대상**, PX4가 보내는 **MAVLink system ID**, **component ID**, **MAVLink IMU ID**를 확인합니다. **비행 중 모델 4종 시작**을 누릅니다. 같은 입력을 사용하는 네 모델의 그래프를 모델 선택 메뉴에서 바꿔 볼 수 있습니다. 관측값은 수신하면서 표시되며, 예측·판정은 입력을 정렬하는 **10초 버퍼**와 필요한 이력이 준비된 뒤 표시됩니다.
5. 실제 비행을 마친 뒤 **비행 종료 · 결과 분석**을 누릅니다. 앱이 원문 기록을 마감하고 사용 가능한 구간으로 종료 후 판정 4종을 계산합니다. 이 버튼은 기록과 분석을 제어하며 기체 착륙·시동 해제는 조종 장치에서 수행합니다. 저장된 비행은 **실시간 비행 모니터링**의 비행 목록에서 다시 열 수 있습니다.

### 3. 기체별 파인튜닝과 판정 기준 보정

같은 기체 프로파일과 같은 입력 방식으로 준비한 로그를 **학습**, **보정**, **독립 평가**로 나눕니다. 같은 원본 또는 같은 날 수집한 로그는 한 역할에 묶습니다. 예를 들어 다른 날짜에 수집한 정상 로그를 학습 2건·보정 1건·독립 평가 1건으로 나누어 작업 흐름을 확인할 수 있습니다. 실제 탐지 성능을 평가하려면 독립 평가에 정상 로그와 확인된 이상 로그가 필요합니다.

| 역할 | **로그 준비 → 비행 용도** | **건강 상태** | 사용 목적 |
| --- | --- | --- | --- |
| 학습 | **적응 학습** | **정상 확인** | 원본 모델의 출력층을 기체 데이터에 맞춤 |
| 보정 | **임계값 보정 전용** | **정상 확인** | 학습과 분리한 정상 비행으로 후보의 판정 기준을 산정 |
| 평가 | **독립 평가·예측** | **정상 확인** 또는 **이상 확인** | 학습·보정에 쓰지 않은 비행에서 오차와 경보를 비교 |

1. 앞의 로그 분석 절차대로 각 파일의 프로파일과 구간을 준비합니다. 표에 맞춰 **비행 용도**, **건강 상태**, 확인 근거를 기록하고 저장합니다.
2. **로컬 AI · 기체 관리 → 파인튜닝 · 보정**에서 모델 하나, 모델군 4종, 전체 8종 중 하나를 고릅니다. **학습 로그**, **보정 로그**, **평가 로그**에서 사용할 구간을 각각 체크하고 **실제 수집 날짜**를 입력합니다.
3. **후보 만들고 독립 평가** 또는 **일괄 파인튜닝·보정**을 누릅니다. 로컬 CPU에서 출력층을 적응하고 별도 정상 로그로 판정 기준을 보정합니다. **작업 결과**에서 예측 오차, 경보 횟수·시간 비율과 비교 그래프를 확인합니다.
4. 원본 모델은 그대로 보존됩니다. 후보 모델과 전용 보정 기준은 **검증 대기**로 함께 저장됩니다. 다시 시험할 비행의 **이 비행의 모델과 판정 기준**에서 후보를 명시적으로 선택하면 두 항목이 함께 적용됩니다. 기본 모델과 다시 비교하려면 **원본 모델 · 기존 기준**으로 바꿉니다.

### 4. 결과 읽기와 문제 확인

- **비행 중 모델**은 팩 전압과 롤·피치·요 각속도를 예측합니다. 그래프에서 모델과 신호를 바꿔 **실측**, **예측**, **잔차(실측−예측)**를 비교합니다. 점수 패널에서 판정 기준과 실제 경보 구간을 확인합니다. **비행 후 모델**은 사용 가능한 비행 기록의 전압 예측을 바탕으로 비행 요약 판정을 제공합니다.
- **이상 의심**은 해당 모델의 판정 기준을 넘었다는 뜻입니다. 실제 신호와 경보 구간을 확인하세요. 사용 구간이나 유효 프레임이 적다면 전체 원본 기록의 길이와 비교해 어느 범위를 채점했는지 봅니다.
- **관측만 나오고 분석이 비어 있으면** 로그는 구간 저장과 분석 실행 여부를, 실시간은 프로파일 선택과 네 모델 시작 여부를 확인합니다. 수신 건수가 0이면 IP·포트·UDP 송신 설정을 확인합니다. 수신 중인데 예측이 보류되면 **데이터 진단**과 화면의 미수신 입력, 기체·IMU ID를 먼저 확인합니다.
- **로그나 후보를 백업하려면** ARION을 닫은 뒤 데이터 폴더를 복사합니다. 기본 위치는 Ubuntu `~/.local/share/arion` (`XDG_DATA_HOME` 설정 시 그 경로의 `arion`), Windows `%LOCALAPPDATA%\ARION`, Mac `~/Library/Application Support/ARION`입니다. 첫 실행 문제를 조사할 때 같은 폴더의 `desktop.log`를 확인할 수 있습니다.

### 시뮬레이션과 데이터 수집

PX4 SITL·Gazebo는 X500 실험을 재현하거나 MAVLink 학습 데이터를 수집할 때 사용합니다. **Ubuntu 24.04 x86_64**, Python 3.12, Gazebo Harmonic 개발 패키지, PX4 빌드 의존성과 user systemd가 필요합니다. 최초 설치에는 소스와 패키지 다운로드가 필요합니다. [설치 사전 조건](docs/data/PORTABLE_SETUP.md#지원-환경과-준비물)

```bash
git clone https://github.com/suha0303/irion.git
cd irion
./Data/generation/drone-data setup --simulation
./Data/generation/drone-data doctor
```

설치 확인 후 다음 명령으로 정상 X500 호버 1건의 MAVLink UDP 원문 수집을 시험합니다. `--out`에는 새 출력 폴더나 이어서 실행할 같은 배치의 경로를 지정합니다.

```bash
./Data/generation/drone-pretrain mavlink \
  --out Data/streamed/mavlink/hover-smoke \
  --scenario hover_normal --duration 90 --seed 17 \
  --count 1 --flight-workers 1 --real-time-factor 1
```

랜덤 데이터 수집은 `--normal-random` 또는 `--abnormal-random`을 사용합니다. 랜덤 모드에서는 기동·바람·임무 길이가 비행별로 달라지므로 `--scenario`와 `--duration`을 빼고 별도 출력 폴더와 목표 건수를 지정합니다. 터미널에서 **`p`**를 누르면 새 비행 배정을 멈추고 진행 중인 비행을 마감합니다. 같은 명령과 출력 폴더로 다시 실행하면 완주 건을 건너뜁니다. 수집한 UDP 원문은 전용 수집 형식으로 저장됩니다. ARION 화면에서 시뮬레이터를 보려면 [실시간 연결](#2-실시간-비행-연결)을 사용합니다.

데이터 수집·정제 작업 메뉴는 `./Data/generation/drone-data menu`로 엽니다. 메뉴의 시험과 작업 제어, 저장 위치, 소스 묶음 내보내기는 설치·운영 문서에서 확인할 수 있습니다. 시뮬레이터 자체 명령은 `./simulation/capstone-sim --help`에서 확인합니다. [수집·정제 운영 안내](docs/data/PORTABLE_SETUP.md#수집과-정제), [시뮬레이터 안내](simulation/README.md)

현재 수집 설정의 이름은 `collection`, 실행 기록의 프로토콜은 `DRONE_COLLECTION`이다. 기체를 지정하지 않으면 X500을 사용하며 수집 프로파일은 `simulation/profiles/collection/`에 있다. 과거 회차 이름은 기존 데이터·봉인된 전처리 패키지의 계보를 읽을 때만 사용한다.

최종 저장 위치는 메뉴에서 지정하며 기본값은 프로젝트의 `Data/`다. 원시·중간 파일은 성공 산출물의 복원 가능성을 검증한 뒤 해당 작업 소유분만 정리한다. 개인 데이터셋·학습 가중치·실행 상태·로컬 설치 환경은 Git 소스에 포함하지 않는다. `export` 명령으로 다른 위치에서 설치할 소스 묶음을 만들 수 있다.

### AI 학습

서버에서 클론한 뒤 `./ai/drone-ai configure`로 서버·기존 Python·데이터·출력 경로를 입력한다. 환경 진단·짧은 GPU 학습/저장/복원 시험·진행 화면은 [서버 사용 안내](docs/ai/PORTABLE_SETUP.md), 비교 구성은 [실험 계획](docs/ai/EXPERIMENT_PLAN.md)을 따른다. 본학습과 다음 회차는 자동 시작하지 않는다. 데이터와 모델·컴퓨터별 설정은 Git 소스와 분리한다.

과거 `v1`·`v7` 등의 운영 이름은 현재 진입 명령이나 설치 경로로 사용하지 않는다. 계약의 schema 식별자·외부 패키지 버전·기존 데이터 계보와 보존 증거는 의미를 유지한다. 범주 이동용 호환 링크는 사용하지 않는다.

기체를 지정하지 않으면 X500을 사용한다. 다른 기체는 [프로파일 안내](docs/simulation/VEHICLE_PROFILES.md)에 따라 시뮬레이션에서 명시적으로 선택한다. 데이터·AI 인수는 현재 X500 전용이다. `drone-data`·`drone-pretrain`은 현재 실행 파일명이며 옛 이름의 호환 링크는 만들지 않는다.
